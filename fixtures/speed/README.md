# Эталон скорости модели (8.4)

Два файла, в которых время каждого запроса посчитано **руками и записано здесь
до того, как появился код парсера**. Метки подобраны круглыми: время ответа
видно вычитанием двух строк таблицы, темп — делением, медиана — сортировкой
шести чисел.

> `expected.json` пересобирать выводом реализации нельзя. Меняется код —
> сверяемся с этой таблицей; меняется таблица — сначала объяснение, почему
> прежний расчёт был неверен, потом код.

Сами `*.jsonl` собирает `scripts/make-speed-fixture.ts` — он только раскладывает
эти метки по записям нужного формата. Живых логов в них нет.

Правило одно на оба провайдера: **время ответа** — от записи, отдавшей модели
промпт, до последней записанной части ответа; **темп** — `output / время` на
каждом запросе, дальше медиана. Где разница не положительна или старта нет —
времени нет (`null`), а не ноль.

- **r1** — старт перед **последней** строкой вместо первой дал бы старт 00:09.500

- **r2** — `deferred_tools_record` пишется вместе с ответом и стоит перед ним с

- **r5** — `file-history-delta` помечен временем **позже** ответа: стартом он
  дал бы −25 000 мс, то есть `null`.
- **r6** — `queue-operation` — сообщение, поставленное в очередь, пока модель
  работала: стартом дал бы 1000 мс вместо 3000.
- **восстановленный** — время соседа приписать ему нельзя: в логе его нет.

### Агрегат `claude-opus-5` за весь период

Измерено шесть: r0, r1, r2, r3, r5, r6.

- время по возрастанию: 3000, 4000, 5000, 6000, 8000, 10000
- **p50** = (5000 + 6000) / 2 = **5500**
- **p90**: позиция (6 − 1) × 0.9 = 4.5 → 8000 + 0.5 × (10000 − 8000) = **9000**
- темп по возрастанию: 10, 20, 30, 50, 80, 100 → **медиана (30 + 50) / 2 = 40.0**
- для сравнения `Σ output / Σ время` = 1550 / 36 с = 43.06 — **не** то, что
  показываем.

`claude-sonnet-5`: измерено два (s1, s2) — ниже порога `SPEED.minRequests` (5),
скорости у модели **нет**.
