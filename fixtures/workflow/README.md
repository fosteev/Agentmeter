# Эталон `workflowReport` (9.3)

Тринадцать корней Claude, тридцать сабагентов и одна сессия Codex, в которых
все показатели экрана Workflow посчитаны **руками и записаны здесь до того, как
появился код**. Числа круглые: расход сессии — сумма пары-тройки запросов, окно
— сумма пяти строк таблицы.

> `expected.json` пересобирать выводом реализации нельзя. Меняется код —
> сверяемся с этой таблицей; меняется таблица — сначала объяснение, почему
> прежний расчёт был неверен, потом код. Арифметика самого `expected.json`
> сверяется независимо в `scripts/check-fixtures.ts` (`npm run fixtures:check`):
> там свой маленький счёт по таблице `sessions` из того же файла.

Сами `*.jsonl` собирает `scripts/make-workflow-fixture.ts` — он только
раскладывает эти числа по записям нужного формата. Живых логов в них нет,
обезличивать нечего.

## Что считается и как

- **Цикл** — корневая сессия (`is_sidechain = 0`), в дереве которой есть
  сабагент с ролью `executor`. Дерево строится по `parent_session_id`
  (`taskSessions`), а не по `sessionId` внутри файла сабагента — там лежит id
  родителя (правило 4). Циклы идут по `started_at` корня: **цикл 1 … 12 — это
  порядок по времени, а не по имени** (по алфавиту `a1 … a6` стоят раньше `b1`).
- **Роль** — корню `main` до всяких правил; сабагенту `roleOf(agentType)` с
  дефолтными правилами: `exec-*` → исполнитель, `review-*` → ревьюер, `plan-*` →
  планировщик, `Explore` → разведка, остальное (`general-purpose`) → `unknown`.
- **Расход** — `input + output + cache_write + cache_read`, как везде (правило 16),
  по всем запросам роли в цикле, восстановленные тоже.
- **Записи** — строки `tool_files` с `action = 'write'` (`Edit`, `Write`). Строки,
  а не разные файлы: `a1-exec` правит `a.ts` дважды, это две записи. `Read` в
  счёт не идёт.
- **`after`** — записи всех узлов цикла, кроме исполнителей, с `requests.ts ≥`
  старт **первого** исполнителя (`>=`: запись ровно в эту миллисекунду входит).
  Правки до старта — промт и roadmap главной сессии — не считаются. Для самого
  исполнителя `writesAfter` всегда ноль.
- **Переделка** точки = Σ `after` ÷ (Σ записей исполнителей + Σ `after`).
- **Накладные** точки = Σ (расход `main` + расход `reviewer`) ÷ Σ расхода
  `executor`. Планировщик, разведка и `unknown` в накладные не входят.
- **Вердикты** — только у ревьюеров, `verdictOf(last_text_head)` с дефолтными
  регулярками. Доля точки = (с оговорками + не принят) ÷ (принят + с оговорками +
  не принят); «вердикта нет» в знаменатель не идёт — так же, как вызовы без
  статуса.
- **Окно** — последние `N = 5` циклов по порядку, **полные** окна: 12 циклов
  дают 8 точек (`n = 5 … 12`, `n` — номер последнего цикла окна, с единицы).
  Значение точки — сумма числителей окна, делённая на сумму знаменателей; нулевой
  знаменатель — точки нет (не нуль).
- **`latest`** — окно, кончающееся на последнем цикле (`n = count`); если у него
  нулевой знаменатель — `null`. **`prev`** — окно без пересечения перед ним, то
  есть кончающееся на `size` циклов раньше (`n = count − size`). `delta =
  latest.value − prev.value`; нет любого из двух — нет и дельты.
- **Ошибки инструментов** — окно в `M = 10` **сессий** (корни и сабагенты, любой
  провайдер) по порядку `(started_at, id)`, а не циклов: точка = Σ вызовов с
  `is_error = 1` ÷ Σ вызовов с известным статусом (`is_error IS NOT NULL`).
  Сессия принадлежит проекту и провайдеру своего корня, а не своего каталога.
- **`approximate`** у точки — в окне есть восстановленные запросы (1.3). Ставится
  **только у накладных**: восстановленный запрос вызовов не несёт, поэтому записи,
  ошибки и вердикты от него не меняются, и у их точек `approximate` всегда `false`
  (приёмка 9.3).
- **`executorUnseen`** — у исполнителей цикла ни одной видимой записи
  (`writes.executor = 0`). Такой цикл в переделку не входит (его часть — 0 / 0), а
  точка переделки называет число таких циклов окна в `unseen`; в ролях последнего
  окна они дают расход, но не записи и не `after` (`roles.unseen`). В эталоне это
  `g1`, `g2`, `g3`: у них и `after` нулевой, поэтому значения точек от исключения не
  меняются, меняется только `unseen`. Случай, где исключение двигает число
  (исполнитель шеллом, главная сессия `Edit`-ом), — синтетика в тесте, граница
  «исполнитель без видимых записей».
- **`until`** — верхняя граница (строго раньше) по началу **корня**: дерево берётся
  целиком, как оно лежит в индексе. Подчинённый, начавшийся позже `until`, остаётся
  в дереве своего корня.

cache_write + cache_read`), их сумма — расход. Каждый запрос раскладывается по

Что здесь нарочно:

- **`a2-rev` — проект `beta` под корнем `alpha`, `b2-exec2` — проект `alpha` под
  корнем `beta`.** Сабагент идёт за корнем: `scope.project = alpha` обязан взять
  `a2-rev` и не взять `b2-exec2`, `beta` — наоборот. Сужение по `sessions.project`
  самого сабагента ошибается в обе стороны разом.
- **`b0` — корень без исполнителя** (с `general-purpose`, который правит файлы, и
  разведкой): цикла нет, и `unknown` исполнителем не становится. **`x1` — второй
  корень без исполнителя**, и он же сессия Codex: пять вызовов, статуса нет ни у
  одного — в окне ошибок она разбавила бы долю, будь знаменатель «все вызовы».
- **`a3`**: запись корня в запросе ровно на метке старта `a3-exec` (10:10:00.000)
  входит в `after` (`>=`). `a3-gp` — `general-purpose`, пишущий «**Принят.**»:
  роль не определена, это не вердикт цикла, а его три записи — `after` роли
  `unknown`, а не исполнителя.
- **`b2`**: два исполнителя (10:10 и 10:40), и запись корня в 10:25 лежит между
  ними. Граница — старт **первого**, значит запись `after`; граница по последнему
  её потеряла бы. У `b2-rev` отказ стоит в теле отчёта: «Принят. Замечаний
  нет.» в первой строке, «вердикт «не принят» относится к нему» ниже — вердикт
  «принят».
- **`b3`**: восстановленный запрос — чтение кэша второго запроса `b3-exec` 900
  при записанных 450, значит между запросами лежит ещё один: `cache_write` 450 +
  `cache_read` 450 = 900. Планировщик переписывает план в 10:35, уже после
  старта исполнителя (10:20), — это `after` роли `planner`.
- **`b1-exec`** пишет «Сделано с оговорками» — отчёт исполнителя, не приёмка, в
  вердикты цикла он не попадает.
- **`g1`, `g2`, `g3`** — проект, где правки идут только через `Bash`: ни одной
  строки `write` ни у кого, переделка по ним не определена.
- Статусы вызовов: ошибка (`is_error: true`) — `!`, явный `false` у `Bash`,
  успех без ключа у остальных (правило 30), вызов без результата — `a3-gp`
  (1) и `b3-exec` (1), у Codex статуса нет ни у одного.

1+1+1+1+1 = 5 (`a1-exec`, `a2-rev`, `a3-exec`, `a5-exec`, `a6-exec`), известных
17+11+16+17+9+18+0 = 88 по деревьям `a1 … a6` и `x1`; с `b2-exec2` вместо `a2-rev`
было бы 92.

**`project-beta`**: циклы `b1 b2 b3` — три, окно пять не набралось: точек нет,
`latest = prev = delta = null`, `count = 3`. Роли — все три цикла. Сессии ошибок:
`b1 b1-exec b1-rev b0 b0-gp b0-expl b2 b2-exec1 b2-exec2 b2-rev b3 b3-plan b3-exec
b3-rev` — 14, без `a2-rev`; `latest` — `n = 14` (окно 5 … 14: ошибок 3, известных
47), `prev` — нет (`n = 4` не точка). Окно во все 14 сессий: ошибок 2+1+1+2 = 6
(деревья `b1`, `b0`, `b2`, `b3`), известных 17+8+19+23 = 67; с `a2-rev` вместо
`b2-exec2` было бы 63.

**`project-gamma`, окно 3 цикла**: циклы `g1 g2 g3`, ни одной записи: переделка
0/0 — точек нет, `latest = null`, `count = 3`. Накладные (2000+1500+1500)/(3000+2500+2000)
= 5000/7500 = 0.6666666666666666 (одна точка, `n = 3`), вердикты — не принят 1,
принят 1, нет 1 → 1/2. Сессии ошибок gamma — девять, окно по умолчанию (10)
не набралось.

**`provider-codex`, окно ошибок 1**: циклов нет (`cycles = []`), но без сужения
они есть — `emptyScope = true`. Сессия одна (`x1`), окно из одной сессии: ошибок
0, известных 0 — точки нет, `count = 1`.

**`provider-claude`**: циклы те же, что в `all`; сессий сорок три (без `x1`),
`latest` — `n = 43` (окно 34 … 43: ошибок 2, известных 39), `prev` — `n = 33`
(окно 24 … 33: ошибок 4, известных 53).

**`project-missing`**: ни циклов, ни сессий; `emptyScope = true`, не «индекс пуст».

## Ловушки и мутации

| ловушка                                              | где лежит в данных                          | мутация |
| ---------------------------------------------------- | ------------------------------------------- | ------- |
| среднее долей вместо суммы к сумме                   | окна с циклами 5 (`a3`) и 10 (`a5`)         | 1       |
| правки главной сессии до старта исполнителя в `after`| циклы 1, 2, 5, 6, 9, 12 (корень пишет до `E`) | 1а   |
| `prev` с пересечением                                | `n = 12` против `n = 7`                     | 2       |
| `unknown` считается исполнителем                     | циклы 5 и 12 (`general-purpose` пишет файлы); `b0` | 3 |
| ошибки делятся на все вызовы                         | `x1` (5 вызовов без статуса), `a3-gp`, `b3-exec` | 4  |
| сабагент чужого проекта попадает в `scope.project`   | `a2-rev` (каталог beta), `b2-exec2` (каталог alpha) | 5 |
| точка с нулевым знаменателем становится нулём        | `project-gamma` (переделка), `provider-codex` (ошибки) | 6 |

Мутации сверх брифа, которые ловит тот же эталон: граница `>` вместо `>=` (цикл 5,
запись ровно на `E`); граница по последнему исполнителю (цикл 6); `Read` считается
записью (все циклы с чтением); записи считаются по разным файлам, а не по строкам
(`a1-exec`); вердикт берётся у всех сабагентов (`b1-exec`, `a3-gp`); окно ошибок и
циклы идут по id вместо времени (порядок `a1 … a6` против `a1 b1 a2 …`). Полный
список и счёт — в «Решениях» [`9.3-report.md`](../../docs/roadmap/9.3-report.md).
