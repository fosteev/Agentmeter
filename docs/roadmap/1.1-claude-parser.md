# 1.1 — Парсер Claude Code

**Кто:** Codex · **Объём:** L · **Блокирует:** 1.3, 1.5, 1.6 · **Ждёт:** 0.2, 0.6

Превращает `~/.claude/projects/<slug>/<sessionId>.jsonl` в нормализованную
модель. Дальше на этих объектах стоит вообще всё, поэтому парсер обязан быть
скучным и буквальным: никаких догадок, никакого «похоже, тут имелось в виду».

## Файлы

```
создать:    packages/core/src/sources/claude/parse.ts
            packages/core/src/sources/claude/live.ts
            packages/core/src/sources/claude/index.ts
            packages/core/test/claude/*.test.ts
не трогать: packages/core/src/sources/types.ts   ← контракт, задан
            packages/core/src/sources/codex/**   ← чужой этап
            fixtures/**                          ← только читать
```

## Контракт

Типы `Session`, `Request`, `ToolCall` заданы в
`packages/core/src/sources/types.ts`. Менять их нельзя. Если чего-то не хватает —
остановиться и сказать, а не дописывать поля.

Публичный интерфейс:

```ts
parseSessionFile(path: string): { session: Session; requests: Request[] }
parseSessionChunk(path: string, fromOffset: number): { requests: Request[]; offset: number }
listLiveSessions(): LiveSession[]   // из ~/.claude/sessions/*.json
```

`parseSessionChunk` нужен индексу (1.5) для дочитывания — он обязан корректно
обрабатывать обрыв на середине строки.

## Что откуда берётся

| поле | источник |
|---|---|
| `Request.input/output/cacheWrite/cacheRead` | `assistant.message.usage.*` |
| `Request.model`, `requestId`, `ts` | `assistant.message.model`, `assistant.requestId`, `timestamp` |
| `Request.skill` | `assistant.attributionSkill` |
| `Request.isSidechain` | `assistant.isSidechain` |
| `Request.contextTokens` | `input + cacheRead + cacheWrite` последнего запроса |
| `ToolCall.name`, `id` | `assistant.message.content[].tool_use` |
| `ToolCall.kind`, `server` | по имени: `mcp__<server>__<tool>` → `mcp`; иначе `builtin` |
| `ToolCall.resultBytes` | длина сериализованного `user.toolUseResult` |
| `Session.title` | запись `ai-title.aiTitle`, последняя в файле |

| `Session.entrypoint` | `~/.claude/sessions/<pid>.json`, поле `entrypoint` |

`ToolCall.marginalTokens` **здесь не считается** — это этап 1.6. Оставить 0.

## Подводные камни

Всё ниже выяснено разведкой по живым логам. Наступать заново не нужно.

1. **`requestId` не уникален построчно.** Один ответ API пишется несколькими
   строками `assistant` — по строке на блок контента — и `usage` в них
   продублирован. Суммировать по строкам нельзя, завысит в разы.

2. **Дедуп по первой строке `requestId` тоже неверен.** Проверено на 16 сессиях
   против эталона Claude Code: даёт стабильный недобор 5–15% по `cacheRead`.
   Причина пока не установлена, разбирается в этапе 1.3. Гипотеза про
   `usage.iterations` проверена и **отпала** — на многоитерационных запросах
   суммы совпадают с верхним уровнем. Реализовать самый прямой вариант, а
   расхождение ловит 1.3.

3. **`usage.iterations`** существует и содержит разбивку по итерациям инференса.
   Не суммировать поверх верхнего уровня — будет двойной счёт.

4. **Не все записи — то, чем кажутся.** В файле встречаются типы `mode`,
   `permission-mode`, `attachment`, `file-history-delta`, `file-history-snapshot`,
   `queue-operation`, `system`, `ai-title`, `last-prompt`. Незнакомый тип —
   пропустить и записать в список неизвестных, а не падать.

5. **Файл читается построчно и лениво.** Самый большой на машине — 5.2 МБ,
   всего 321 МБ по 590 файлам. `JSON.parse` на каждую строку, битую строку
   пропустить и посчитать.

6. **`toolUseResult` может быть огромным** и его размер не равен тому, что ушло
   в промпт. Читать его длину, не содержимое; в память результат не тащить.

7. **Живые сессии — отдельный источник.** `~/.claude/sessions/<pid>.json`
   переживает смерть процесса, поэтому pid обязательно проверять на живость,
   иначе в трее навсегда повиснут мёртвые агенты.
