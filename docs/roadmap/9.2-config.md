# 9.2 — Раздел `workflow` в конфиге

**Кто:** sonnet, high · **Объём:** S · **Блокирует:** 9.3, 9.5, 9.6

Всё, что в Workflow зависит от того, как пользователь устроил свою работу, —
настройка, а не константа продукта: какой `agentType` кем считать, как выглядит
вердикт, сколько циклов брать в окно, где цель и порог. Если этап сделать плохо,
неизвестный субагент молча станет исполнителем, а битая регулярка уронит main при
старте.

## Контракт

```ts
type WorkflowRole = 'executor' | 'reviewer' | 'planner' | 'explore' | 'unknown'
type Verdict = 'accepted' | 'notes' | 'rejected' | 'none'

Config.workflow: {
  enabled: boolean                                   // false
  roles: Array<{ match: string; role: Exclude<WorkflowRole, 'unknown'> }>
  // дефолт: exec-* → executor, review-* → reviewer, plan-* → planner, Explore → explore
  verdicts: { rejected: string; notes: string; accepted: string }   // регулярки, флаг i
  // дефолт: «не принят|not accepted|rejected», «с оговорками|with notes», «принят|accepted»
  window: { cycles: number; sessions: number }       // 10, 20
  target: { rework: number | null }                  // null — цели нет
  alerts: { rework: number | null; errorRate: number | null; overhead: number | null }  // null — выкл
}
```

- `match` — glob только с `*`, регистр учитывается. Правила проверяются по
  порядку, побеждает первое совпадение. Ничего не совпало — `'unknown'`.
- Вердикт проверяется в порядке `rejected → notes → accepted` по первым 200
  символам: «не принят» содержит «принят», поэтому порядок важен. Ничего не
  совпало — `'none'`.
- Регулярка, которая не компилируется, отклоняется валидатором с путём ключа.
  Вместо неё используется дефолт, main не падает.

**По реальному коду (9.1, 25 октября).** `sessions.last_text_head` — первые 200
**кодпоинтов** последнего непустого текстового блока сабагента, как они написаны:
с разметкой (`**Принят с оговорками.**`) и с ведущими пробелами, если они есть, —
поэтому регулярки вердикта обязаны искать по подстроке (флаг `i`, без `^`), как в
дефолтах выше. `NULL` — у корневых сессий, у Codex и у сабагентов без единого
текста: на диске их 71 из 866, среди них 7 из 35 `review-opus`. Для таких
`verdictOf` получает «текста нет» и отвечает `'none'`, а не падает на `null`.
Живой набор `agentType` на 25 октября, 866 сабагентов: general-purpose 582,
Explore 100, workflow-subagent 81, review-opus 35, plan-opus 33,
exec-sonnet-high 27, exec-sonnet-medium 5, exec-opus-high 2, exec-sonnet-max 1 —
числа «Данных» ниже выросли, состав тот же.

## Подводные камни

- `t()` не звать на верхнем уровне модуля (правило i18n). Подписи ролей — ключи,
  а не строки.
- Дефолтные регулярки — на двух языках: русский для пользователя, английский для
  остальных.

**Решения (25 октября, по итогам сессии 9.2):**

- **Раскладка.** Типы `WorkflowRole`, `AssignableRole`, `Verdict`, `WorkflowRule`,
  `WorkflowConfig` — в `config/types.ts` рядом с `Config`, а не в `workflow/roles.ts`:
  конфиг — нижний слой, и `roles.ts` импортирует его, а не наоборот (иначе цикл
  `types.ts ⇄ roles.ts`). `roles.ts` их реэкспортирует. `config/validate.ts`: правила
  `workflow.verdicts.*` (`compilesAsVerdict`), `workflow.window.*`, `workflow.target.*`,
  `workflow.alerts.*` в `RULES`; новый `SHAPES` для списка объектов `workflow.roles`;
  `Rule.expected` теперь может быть функцией (`expectedText`) — иначе `t()` пришлось бы
  звать на верхнем уровне. `config/load.ts`: `walk` зовёт `SHAPES`. Всё экспортировано из
  `index.ts` ядра: `roleOf`, `verdictOf`, `roleLabel`, `verdictLabel`, `ROLE_LABEL_KEYS`,
  `VERDICT_LABEL_KEYS`, типы. i18n: раздел `workflow` (подписи ролей и вердиктов),
  в `config` — `typeObject`, `expectedRegex`, `badRoleRule`, оба языка.
- **Контракт — как в брифе, плюс уточнения.**
  - `roleOf(agentType, rules)`: `null`/`undefined`/`''` → `unknown`. Корневая сессия тоже
    `unknown`: роль `main` из 9.3 назначает запрос по `is_sidechain = 0` **до** вызова
    `roleOf`, а не `roleOf`. Шаблон — только `*` (любая подстрока, включая пустую и
    дефисы), всё остальное буквально, регистр учитывается, совпадение целиком.
  - `verdictOf(text, verdicts)`: первые 200 **кодпоинтов**, флаг `i`, подстрока, порядок
    `rejected → notes → accepted`; `null`/`undefined`/`''` → `none`. Регулярка, которая не
    компилируется (или совпадает с пустой строкой), подменяется дефолтной для **этого**
    вида — и в валидаторе, и в самой функции, если её позвали мимо загрузчика.
  - Битая регулярка в файле: замечание `workflow.verdicts.<вид>: допустимо …, пришло "…" —
    взят дефолт`, остальные настройки принимаются. Негодное правило роли выбрасывается по
    одному (`workflow.roles[2]: …— правило пропущено`), порядок остальных цел; `roles` не
    списком — дефолт; `roles: []` законно и значит «ролей нет, все `unknown`».
- **Отступления от брифа и почему.**
  1. Дефолтные регулярки с `\s+` вместо пробела: `не\s+принят|not\s+accepted|rejected`,
     `с\s+оговорками|with\s+notes`, `принят|accepted`. Голова хранится как написана, и
     между словами может оказаться двойной/неразрывный пробел или перенос; смысл прежний.
  2. Валидатор отклоняет регулярку, совпадающую с пустой строкой (`''`, `a*`, `(?:)`), и
     длиннее 200 знаков: такая совпала бы с любым текстом, и каждая приёмка стала бы
     `rejected` без единого сигнала. Шаблон роли — непустой, до 200 знаков.
  3. **Единицы порогов — доли, а не проценты** (см. «Скоуп» в отчёте): `target.rework` и
     `alerts.rework`/`errorRate` — 0..1, `alerts.overhead` — кратность 0..1000. Бриф
     единиц не называл; это те же единицы, в которых будет считать `workflowReport`, и
     порог сравнивается с `latest` без ×100. `20` вместо `0.2` отклоняется валидатором
     (тест), а не принимается как «цель 2000%».
  4. Диапазоны окна: `cycles` 1..1000, `sessions` 1..100000 (в брифе диапазона нет).
- **Известные пределы (не чинились).** Поиск по подстроке: «Принятые решения…» совпадёт с
  `принят`, а `\b` с кириллицей в JS не работает (границы слова только ASCII). Регулярка
  пользователя с катастрофическим бэктрекингом (`(a+)+b`) повесит main на 200 знаках:
  запретить такой класс нельзя без разбора регулярки, а источник — собственный конфиг
  пользователя; длина ограничена 200.
- **Проверено.** `roleOf` — все 9 живых `agentType` (general-purpose, workflow-subagent →
  `unknown`), регистр, якорность, экранирование, порядок; `verdictOf` — четыре живые
  строки из «Данных», `не принят`/двойной и неразрывный пробел, порядок, английский, срез
  по 200 кодпоинтам (эмодзи), `null`, битая/пустая регулярка; конфиг — дефолты, битая
  регулярка с путём ключа, роли по одному, `applyPatch` откатывает к текущему, круг
  `saveConfig → loadConfig`, замечания по-английски без кириллицы. 24 мутации (инверсия
  `unknown`, регистр, якоря, экранирование, порядок вердиктов, срез по UTF-16, `null`,
  отсутствие защиты от пустой, диапазоны, обход `SHAPES`) — 20 красных; 3 пережили как
  эквивалентные (ранний выход `length <= 200` — оптимизация; `catch → /(?:)/` ловится
  защитой «совпадает с пустой»; `length === 0` дублируется ею же). Мутация диапазона
  `target.rework` 0..100 — четвёртая выжившая, не эквивалентная: добавлен тест на «20 вместо 0.2».
- **Не проверено.** Раздел настроек (9.5) и работа с реальным `config.json` пользователя
  не трогались; живой `agentType`/`last_text_head` на настоящем индексе не гонялись (проба
  — в 9.3, `workflow-live.ts`).

**Приёмка (25 октября).**

- **Вердикт — только в первой содержательной строке** (первая строка с буквой или цифрой
  в голове 200 кодпоинтов; строки из одной разметки `---`, `**` пропускаются). Подстрока
  без `^` осталась (решение 9.1), сужена область. Причина: порядок `rejected → notes →
  accepted` отдаёт первенство отказу, и фраза в теле отчёта («решение по кэшу не
  принято») перебила бы вердикт первой строки. Якорь к началу после снятия разметки
  отвергнут: на живых головах вердикт стоит и после `**Вердикт:**`, и после «Этап 1».
  Замер на копии живого индекса (35 `review-opus`): **accepted 14, notes 10, rejected 0,
  none 11** (7 без текста, 4 — промежуточные реплики вроде «Чисто. Коммичу…», вердикта в
  них нет), ни одного промаха; у всех 24 вердиктов он в первой строке, и распределение с
  сужением и без него совпало. Цена: вердикт под заголовком (`## Приёмка\n\nпринят`) —
  `none`, видимое «вердикта нет», а не выдуманный ответ. Тесты — блок «первая
  содержательная строка», без сужения краснеют два.
- **Единицы порогов — доли, как у исполнителя, принято.** Прецедент в конфиге двоякий:
  `alerts.warnAtPercent` — проценты, но потому что сравнивается с `usedPercent`, который
  провайдер отдаёт процентом, и единица записана в имени; `limits.claude.cacheReadWeight`
  и все `share` контракта IPC — доли 0..1. Правило одно: порог в единицах того, с чем
  сравнивается, а `workflowReport` считает отношения сумм (9.3) — доли и кратность.
- **Бэктрекинг.** Предела по времени не добавлено: синхронную регулярку в JS не прервать,
  а вход и так узкий — одна строка до 200 кодпоинтов на сессию-ревьюера (десятки за
  отчёт, не на каждый запрос), шаблон до 200 знаков, источник — собственный конфиг.
  Записано пределом в `verdictOf` и в pending.
- **Починено:** `integer`/`numberOrNull` в валидаторе писали «целое 1..1000» литералом —
  в английских замечаниях про `workflow.window.*` и пороги ехала кириллица; теперь
  `config.expectedInteger`/`expectedNumberOrNull` через `t()` (тест «замечания переведены
  на английский» расширен на окно и порог).
- Проверено без правок: путь загрузки битого конфига не бросает (`JSON.parse` в `try`,
  `walk`/`SHAPES` без исключений, `compilesAsVerdict` гоняет регулярку только на `''`);
  `general-purpose`/`workflow-subagent` → `unknown`; `t()` на верхнем уровне нет.
  Потолки длины подписей ролей в `i18n/limits.ts` — в 9.5, когда известна ширина макета 9.4.
