# 1.7 — Рекуррентная стоимость: из чего складывается стартовый префикс

**Кто:** модель — сам, код — Codex · **Объём:** M · **Блокирует:** 4.1, 4.2, 4.3

Стартовый префикс — системный промпт, схемы тулов, листинги скиллов и
сабагентов, инструкции MCP-серверов, `CLAUDE.md` и первый ход пользователя.
Он записывается в кэш один раз, а перечитывается на **каждом** запросе сессии,
поэтому это не разовая, а рекуррентная статья: 30 000 токенов префикса при 12
запросах — это 360 000 токенов чтения кэша. На типичной сессии префикс — 27–37
тысяч токенов, из которых три четверти неотделимы от системного промпта.

Без этого этапа нечем ответить на главный вопрос продукта — «что отключить,
чтобы стало дешевле». Сделать плохо — значит показать пользователю уверенную
цифру экономии, которой не будет: разница между жадным и отложенным режимом
MCP составляет 18 раз, и перепутать их — соврать на порядок.

## Контракт

В `sources/types.ts` добавить (менять существующие поля нельзя):

```ts
type PrefixCategory =
  | 'system'          // системный промпт и схемы вшитых тулов
  | 'toolSchemas'     // схемы тулов, когда они видны отдельно (Codex)
  | 'deferredTools'   // имена отложенных вшитых тулов
  | 'mcpTools'        // имена отложенных тулов MCP, по серверам
  | 'mcpInstructions'
  | 'skills'
  | 'agents'
  | 'memory'          // CLAUDE.md, AGENTS.md, файлы памяти
  | 'userTurn'

interface PrefixBlock {
  category: PrefixCategory
  source?: string     // имя MCP-сервера — по нему считается экономия в 4.3
  bytes: number       // UTF-8, не символы
  tokens: number
  basis: 'estimated' | 'residual'
}

interface Session {
  // ...
  prefixTokens: number        // ctx первого записанного запроса
  prefixBlocks: PrefixBlock[]
  toolsDeferred: boolean      // в наборе был ToolSearch
}
```

Сигнатура, по образцу `attributeMarginal` из 1.6:

```ts
export function attributePrefix(
  session: Session,
  requests: Request[],
  options?: PrefixOptions,
): PrefixBlock[]
```

Константы «байт на токен» — в `calibration.ts`, отдельной таблицей на категорию,
со ссылкой на стенд и датой замера. Значения — из
[`fixtures/prefix/README.md`](../../fixtures/prefix/README.md), раздел «Байт на
токен». Одной общей константы быть не должно: список имён тулов плотнее прозы
в полтора раза.

Правила счёта (округление, дележ блока между серверами, знак остатка) — там же,
раздел «Правила счёта». Дележ обязан быть тем же детерминированным правилом
наибольшей дробной части, что в `splitResidual` (1.6): переиндексация не имеет
права менять цифры.

## Критерий готовности

```bash
npm run check                                                  # +тесты prefix
npm run fixtures:check
node --experimental-strip-types scripts/probe/prefix-live.ts
```

`prefix-live.ts` — шесть проверок, все обязаны быть ✓, код возврата 0:

1. **Тождество.** `Σ tokens по блокам = prefixTokens` до токена на всех сессиях.
   Ловит только арифметику, но ловит её насмерть.
2. **Остаток положителен.** `system` (у Codex — `toolSchemas`) ни на одной
   сессии не отрицателен. Отрицательный — категории переоценены.
3. **Парная сверка коэффициентов.** Внутри группы (версия CLI, модель, проект)
   для всех пар сессий, где расчётные категории разошлись на ≥ 800 токенов,
   медиана `Δ prefixTokens / Δ Σ категорий` = **1.00 ± 0.10**. Это
   единственная проверка не против самих себя: коэффициенты калибровались
   стендом, а сверяются с живыми логами. Пар должно набраться ≥ 300.
4. **Стабильность остатка.** Внутри группы (версия, модель, проект) с n ≥ 5
   разброс `system` p10..p90 от медианы ≤ 10%. Групп, проходящих порог, — не
   меньше 10.
5. **Режим определяется.** На сессиях с `toolsDeferred = true` доля `mcpTools`
   в префиксе < 5%; на сессиях с `false` блока `mcpTools` нет вовсе, и это
   отражено в тексте пробы, а не молча.
6. **Codex.** Раскладка сходится тождеством (проверка 1) на всех роллаутах,
   `base_instructions` найден в ≥ 95% из них. Пороги 3 и 4 у Codex **не
   проверяются** — константы там не калиброваны, проба печатает медиану
   отношения для сведения и всё.

## Данные

- `fixtures/prefix/README.md` — разложение, посчитанное руками до кода. Три
  сессии: Claude отложенный, Claude жадный, Codex. Каждый блок ровно 1000
  токенов, всё проверяется в уме.
- `fixtures/prefix/*.expected.json` — ожидаемый ответ. **Пересобирать выводом
  реализации нельзя ни при каких обстоятельствах.** Не сходится — спорить надо
  с таблицей в README, а не править json.
- `scripts/make-prefix-fixture.ts` — собирает `*.jsonl` из этих чисел, по
  образцу `scripts/make-oracle-fixture.ts` (1.6). Добивает блоки до заданной
  длины **в байтах UTF-8**.
- Живые логи: `~/.claude/projects/*/*.jsonl` (≈ 310 сессий верхнего уровня),
  `~/.codex/sessions/**/rollout-*.jsonl` (≈ 330).
- `scripts/probe/calibrate-prefix.sh` — стенд, которым получены константы.
  Запускать не нужно: числа уже в `calibration.ts`. Нужен, когда выйдет новая
  версия CLI и остаток поедет.

## Подводные камни

1. **Блоки префикса лежат в записях `attachment`, парсер их сейчас выбрасывает.**
   `attachment` числится среди известных, но игнорируемых типов в
   `sources/claude/parse.ts`. Нужные подтипы и поля:
   `skill_listing.content`, `agent_listing_delta.addedLines`,
   `deferred_tools_delta.addedNames`, `mcp_instructions_delta.addedBlocks`,
   `nested_memory.content`. Считать надо длину **отрендеренного** текста
   (`addedLines` склеиваются `\n`, `addedBlocks` — `\n\n`), а не длину JSON
   записи: разница в полтора раза.

2. **Байты — это UTF-8, а не `String.length`.** На листинге скиллов с русскими
   описаниями `length` даёт 11 811, а байтов 13 929. Ошибка в 18% ровно там,
   где всё считается из байтов. Везде `Buffer.byteLength(s, 'utf8')`.

3. **Отложенные тулы меняют цену MCP в 17 раз.** Замер стендом на 2.1.226:
   сервер serena (23 тула) стоит **6007** токенов, когда схемы едут в префикс
   жадно, и **349** токенов, когда в наборе есть `ToolSearch` и в префикс едут
   одни имена. На 2.1.85 — 5998 против 326, то есть цифры устойчивы к версии.
   Признак режима — наличие записи `deferred_tools_delta`. В жадном режиме схем
   MCP в транскрипте нет вовсе, и они неотделимы от системного промпта: их
   место — в остатке, а не в нулевом блоке `mcpTools`.

4. **Первый ход пользователя плотнее документации.** 3.02 байта на токен против
   4.11 у markdown. Это не мелочь: пары живых сессий внутри одного проекта
   отличаются в основном длиной первого промпта, и с общей константой 4.11
   отношение `Δфакт/Δрасчёт` выходило **1.36**, а не 1.00. Именно эта проверка
   (пункт 3 критерия) поймала неверный коэффициент — она и есть главный тест
   этапа, а не тождество.

5. **`ctx` первого запроса — не `cacheWrite`.** На 300 живых сессиях из 311
   первый запрос уже читает кэш: префикс записан предыдущей сессией в том же
   проекте. Брать `input + cacheWrite + cacheRead`. Формулировка критерия в
   роадмапе («= первому `cacheWrite`») в этом месте неточна, и это её поправка.

6. **`requestId` схлопывать, как в 1.1.** Первая строка `assistant` даёт
   полные `input/cache_*`, но частичный `output`. Для префикса нужны первые
   три, так что первой строки достаточно, — но брать их надо из схлопнутого
   запроса, а не из сырой строки, иначе повторится ошибка 1.1.

7. **Скиллов и сабагентов в `-p` нет.** Стенд `claude -p` не подмешивает
   листинги скиллов и агентов вовсе — они появляются только в интерактивном
   режиме. Поэтому их байты меряются «весами» (текст кладётся в `CLAUDE.md`), а
   не разностью конфигураций. На это уже наступили, повторно проверять не надо.

8. **Потульные замеры не складываются — не пытаться разложить остаток по тулам.**
   На 2.1.85 схемы были аддитивны до токена (`Bash` 3073 + `Read` 611 =
   `Bash,Read` 3684). На 2.1.226 то же измерение даёт `Bash` 3866, `Read` 1530,
   а вместе — 4553 вместо 5396: набор влияет на то, что CLI решит отложить.
   Поэтому стендом меряется **вес набора целиком** (14 245 токенов на
   `--tools default`), а `system` остаётся одним блоком. Разбивать его по
   отдельным тулам в интерфейсе — придумывать.

9. **У Codex всё наоборот.** Системный промпт лежит в логе дословно
   (`session_meta.base_instructions`, ≈ 12 КБ), а остатком оказываются схемы
   тулов. Раскладка та же, меняется только то, какой блок остаток. Константы
   б/т у Codex **не калиброваны** — токенизатор другой, стенда не было. Наследуют
   значения Claude и помечаются оценкой; порог по ним не проверяется (пункт 6).

10. **В PATH две установки CLI, и стенд молча берёт не ту.** `/opt/homebrew/bin/claude`
    отстаёт от нативной `~/.local/bin/claude` на полтораста версий (2.1.85
    против 2.1.226). Первый прогон стенда снял числа со старой — а расходятся
    они вдвое: схемы вшитых тулов 10 898 против 14 245. Скрипт теперь выбирает
    свежайшую и печатает версию первой строкой; любые числа стенда без версии
    рядом — мусор.

11. **Глобальный `CLAUDE.md` и файлы памяти в раскладку не попали.** Считается
    только `CLAUDE.md` из корня проекта. Здесь `~/.claude/CLAUDE.md` — это 2395
    байт, около 580 токенов в префиксе каждой сессии, и они оседают в остатке
    `system`. Критерий этого не ловит: величина постоянна на машине, а проверки
    смотрят на разности и разброс. Чинить в парсере нельзя — чтение домашнего
    каталога делает тесты машинозависимыми; правильное место — опция с путями
    из `config.sources`.

12. **Не путать с 1.6.** Прирост в середине сессии — сервер подключился позже,
    `ToolSearch` подтянул схемы — это маржинальная дельта, её уже считает
    `marginal.ts`. 1.7 — только то, что уехало в промпт до первого ответа.
