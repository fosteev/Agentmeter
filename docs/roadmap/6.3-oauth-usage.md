# 6.3 — Лимиты по требованию: `oauth/usage` вторым источником

**Кто:** Codex, модель и эталон — сам · **Объём:** L · **Блокирует:** 1.9 (даёт
ему точки там, где `statusLine` не зовётся)

Процент лимита Claude в транскрипт не пишется, и до сих пор его отдавал только
хук строки состояния (1.9). Но `statusLine` — фича терминального TUI: в
VS Code-расширении она не рисуется, команда не вызывается, и журнал наблюдений
остаётся пустым **навсегда**, а не «копится медленно». Замер на машине автора,
11 августа: хук установлен и исправен (ручной прогон пишет снимок, `exit 0`),
`~/.claude/settings.json` на него указывает — а `usage-latest.json` и
`usage.jsonl` не появились за 7.5 часов. Этап открывает второй источник тех же
чисел, который от способа запуска агента не зависит: тот же ответ, что Claude
Code кладёт в `cachedUsageUtilization`, но запрошенный тогда, когда он нужен.

Цена ровно одна и названа прямо: **это второй сетевой вызов продукта, и он
идёт чужими креденшелами.** Поэтому он выключен по умолчанию, включается
осознанно и описан в README теми же словами, что и проверка обновлений. Сделать
его плохо — значит либо тихо начать ходить в сеть за спиной у человека, купившего
продукт за обещание «всё считается из логов на диске», либо выдать целый процент
за дробный и испортить калибровку, ради которой всё и затевалось.

## Контракт

**Снимок — тот же.** [`UsageSnapshot`](../../packages/core/src/limits/usage.ts)
получает одно новое поле и ни одного больше:

```ts
/** Откуда снимок. Отсутствие поля читается как 'statusline' — журнал старше этапа. */
source?: 'statusline' | 'oauth'
```

Журнал остаётся один (`usage.jsonl`), дедуп — существующий `usageKeys`, по паре
(процент, момент сброса). Второй файл завёл бы второй порядок записей и второй
дедуп на те же наблюдения.

**Статус для экрана** — рядом с
[`UsageHookStatus`](../../packages/ipc/src/index.ts), не внутри него: хук и
запрос включаются порознь и ломаются порознь.

```ts
export interface UsageApiStatus {
  /** Настройка включена человеком. Выключено — остальные поля про прошлое. */
  enabled: boolean
  /** Токен нашёлся: файл `.credentials.json` или Keychain. */
  credentials: 'file' | 'keychain' | 'missing'
  /** Когда снимок получен, мс. Нет — ни одного удачного ответа не было. */
  fetchedAt?: number
  /** 401: Claude Code разлогинен или токен протух — нужен `claude login`. */
  needsLogin: boolean
  /** Активное окно 429 — до этого момента запросов не будет, мс. */
  retryAt?: number
  /** Текст последней ошибки. Наш пересказ, а не тело ответа: в нём бывает токен. */
  problem?: string
}
```

**Канал** — `oauth:set` (`{ enabled: boolean }` → `ConfigReport`, как у
`statusline:set`) и `oauth:refresh` (без аргумента → `UsageApiStatus`) для кнопки
«Обновить сейчас».

**Конфиг** — `limits.claude.api: { enabled: boolean }`, по умолчанию `false`.
Значение по умолчанию менять нельзя ни в какой ветке: включение — это согласие,
а согласие по умолчанию не бывает.

## Модель

### Что отдаёт эндпоинт

`GET https://api.anthropic.com/api/oauth/usage`, заголовки
`Authorization: Bearer <accessToken>`, `anthropic-beta: oauth-2025-04-20`,
`Accept: application/json`. Живой ответ 11 августа 2026 — в
`fixtures/oauth/usage-live.json`.

Разбирать **массив `limits`**, а не именованные поля. В ответе рядом с
`five_hour` и `seven_day` лежат `seven_day_opus`, `seven_day_sonnet`,
`seven_day_oauth_apps`, `seven_day_cowork`, `seven_day_omelette` и полдюжины
кодовых имён (`tangelo`, `iguana_necktie`, `nimbus_quill`, `omelette_promotional`,
`cinder_cove`, `amber_ladder`) — все `null` на замеренном аккаунте, кроме
`nimbus_quill` с нулём и `resets_at: null`. Перечислять их поимённо значит
подписаться на чужой ритм переименований. В массиве та же информация размечена:

```json
{ "kind": "weekly_all", "group": "weekly", "percent": 19, "severity": "normal",
  "resets_at": "2026-08-16T05:00:00.668875+00:00", "scope": null, "is_active": true }
```

Берём `kind: "session"` → `fiveHour`, `kind: "weekly_all"` → `weekly`. Записи с
`resets_at: null` пропускаем — окна без границы в модель 1.9 не входят, ей нужен
интервал. `weekly_scoped` (на замеренном аккаунте — Fable, `is_active: false`)
в этом этапе не показывается и в журнал не пишется: `UsageWindowKind` — часть
контракта 1.9, и расширять его ради окна, которое пока всегда неактивно, значит
менять контракт под гипотезу.

`resets_at` — ISO 8601 с микросекундами и зоной (`+00:00`), а **не** секунды, как
на stdin у `statusLine`. В журнал, как и там, идут миллисекунды.

### Точность: проценты целые

`five_hour.utilization: 0.0`, `seven_day.utilization: 19.0`, в массиве —
`percent: 0` и `percent: 19`. Это тот же дефект, из-за которого отвергнут
`cachedUsageUtilization` (пункт 3 в [1.9-usage.md](1.9-usage.md)), и не
случайно: сверка показала, что `cachedUsageUtilization` — **дословно то же
тело**, те же поля и те же кодовые имена. Разница между источниками одна, и она
в свежести: в файле `fetchedAtMs` показывал возраст 3.5 часа в момент, когда сам
файл был переписан минутой раньше.

Отсюда правило отбора, которое добавляется в
[`CALIBRATION`](../../packages/core/src/limits/usage.ts):

```ts
/**
 * Наименьший процент, при котором целочисленный снимок берётся в систему.
 * Квантование ±0.5 п.п. при `p = 1` — это 50% относительной ошибки, при
 * `p = 10` — 5%, и потолок, выведенный по первым, уедет в разы.
 */
minIntegerPct: 10,
```

Дробные снимки (`statusline`) порога не имеют — у них квантования нет.
Смешивать источники в одном решении **можно**: система линейна по `(cap, w)`, и
точка с большей погрешностью просто весит столько же, сколько остальные, — но
только после отбора. Остаток (`residualPp`) при этом считается по всем точкам,
и порог в 2 п.п. остаётся прежним: целочисленный снимок вносит в него не больше
0.5 п.п.

### Ходить обязан Chromium, а не Node

Замер 11 августа, один и тот же токен и одни и те же заголовки:

| чем                | ответ |
| ------------------ | ----- |
| `curl`             | 200   |
| Electron `net.fetch` (Chromium) | 200 |
| `fetch` из Node (undici) | 403 |
| `node:https` (HTTP/1.1)  | 403 |
| `node:http2`             | 403 |

Заголовки и версия протокола проверены порознь и ни при чём: `node:https`
отправлял ровно то же, что `curl`, и всё равно получил 403. Отсекает Cloudflare
по отпечатку TLS — Node в его белый список не входит.

Отсюда правило: `OauthHost.fetch` в приложении получает **`net.fetch` из
Electron**. Ошибиться здесь дёшево и незаметно: с Node-фетчем источник не
заработал бы ни у кого, а на экране это выглядело бы как «Anthropic не принял
токен» — то есть человек пошёл бы перелогиниваться в Claude Code, и не помогло
бы.

По той же причине живой режим пробы гоняет запрос **под Electron**, а не из
самой пробы: проверка, ходящая не тем стеком, что приложение, проверяет не то.

### Свежесть и 429

Кэш снимка — 15 минут. Один вызов после суток тишины 429 не дал и `Retry-After`
в ответе не прислал, но ClaudeBar (`ClaudeAPIUsageProbe.swift`) документирует
часовые окна `Retry-After` в ответ на единственный вызов после паузы, со ссылкой
на anthropics/claude-code#30930. Отсюда три правила:

1. **`Retry-After: 0` не значит «можно сразу».** Эндпоинт наблюдался отдающим
   ноль и продолжающим 429-ить. Ноль и отрицательное отбраковываются, вместо них
   — 5 минут.
2. **Заголовок бывает и HTTP-датой**, не только секундами (RFC 7231).
3. **401 не ретраится вовсе.** Токен протух или Claude Code разлогинен —
   повторять бессмысленно, статус переходит в `needsLogin`, и следующая попытка
   только по кнопке.

### Креденшелы: только чтение

Токен берётся из `~/.claude/.credentials.json`, а если файла нет — из Keychain:
`security find-generic-password -s "Claude Code-credentials" -w`, поле
`claudeAiOauth.accessToken`. На замеренной машине файла нет вовсе, лежит в
Keychain — ветка обязательна, а не «на всякий случай».

**Рефреша токена у нас нет и не будет.** ClaudeBar его делает (через
`platform.claude.com/v1/oauth/token` с client_id Claude Code) и записывает
результат обратно в Keychain — то есть переписывает чужие креденшелы. Мы этого
не делаем: токен живёт ~8 часов и обновляется самим Claude Code, а работающий
Claude Code — предусловие всего продукта. Протух — показываем «нужна
авторизация». Цена ошибки несимметрична: наш неудачный рефреш может выбить
человека из CLI, а неудача чтения стоит одной серой строки на экране.

Токен не логируется, в `problem` не попадает и в IPC не уходит ни в каком виде.

### Что показываем

Полученный процент — **факт от провайдера**, и он точнее любого нашего расчёта:
снимается пометка «оценка» с окон, у которых есть свежий снимок, а рядом
подписывается источник. Дальше он не подменяет собой ленту: расход по-прежнему
считается из логов, а процент лежит рядом как второе число. Причина в пункте 21
CLAUDE.md — процент считается **по аккаунту**, наш расход по машине, и работа с
другого устройства расходится с нашим расчётом законно.

### Границы окна тоже от провайдера, и это замер, а не вкус

Первая версия подставляла в наши окна только процент. Сверка с живым ответом
показала, что так делать нельзя: **наши границы промахиваются**.

| что                   | пятичасовое окно Claude, 11 августа |
| --------------------- | ----------------------------------- |
| наш расчёт            | 16:40 – 21:40 UTC                   |
| ответ провайдера      | 19:40 – 00:40 UTC                   |

Ровно три часа мимо. И это не «якорь чуть уехал»: пятичасовой паузы в запросах
не было вовсе — самая большая за день 82 минуты (18:12 → 19:34), то есть
правило «окно якорится на первом обращении после истечения прошлого» на этих
данных вообще не могло дать 19:40.

Причина та же, что у `foreign` в 1.9: **лимит считается по аккаунту**. Окно
могло начаться с запроса, которого у нас нет, — с другой машины, из веба, из
Claude Desktop, — и наша цепочка окон, выстроенная по одной машине, разъезжается
с провайдерской молча. Восстановить это из логов нельзя, потому что чужих
запросов в логах нет по определению.

Поэтому окно Claude **заменяется целиком**, а не дополняется процентом:
процент от одного интервала рядом с «сброс через» от другого — это две правды,
складывающиеся в ложь. Половинчатый вариант ловится мутацией
(`startsAt` со сдвигом на три часа роняет проверку в `reports.test.ts`).

Наш расчёт при этом остаётся живым и нужным: он работает, когда источник
выключен или недоступен, — и тогда честно помечен оценкой.

## Критерий готовности

```bash
npm run check
npm test -w packages/core -- oauth
npm test -w @agentmeter/desktop -- oauth
node --experimental-strip-types scripts/probe/oauth-live.ts
```

Проба обязана:

- при выключенной настройке **не делать ни одного сетевого вызова** — проверяется
  подменённым `fetch`, который падает при вызове (это отдельная проверка, а не
  примечание: тихо включившийся источник — главный способ сломать этот этап);
- разобрать `fixtures/oauth/usage-live.json` в два окна с процентами 0 и 19;
- на 429 с `Retry-After: 0` назначить окно 5 минут, а не ноль;
- на 401 выставить `needsLogin` и не ходить повторно;
- напечатать, сколько точек журнала пришло из какого источника.

## Подводные камни

1. **Ответ содержит поля, которых мы не понимаем, и это норма.** Кодовые имена
   (`tangelo`, `nimbus_quill`) — чужие эксперименты. Разбор обязан быть терпимым
   к неизвестному и нетерпимым к неверному: незнакомый ключ пропускается молча,
   а `percent` вне 0…100 или отрицательный `resets_at` роняют **запись**, а не
   весь ответ.
2. **`spend` и `extra_usage` в этом этапе не показываются.** Форма разобрана
   (`amount_minor` + `exponent`, минорные единицы), но на замеренном аккаунте
   выключено и то и другое, а показывать деньги, не увидев их ни разу вживую, —
   ровно то сочинение, против которого написан раздел «Границы честности».
3. **Пятичасовое окно бывает нулевым сразу после сброса.** В эталонном ответе
   `five_hour: 0.0` при активной работе — окно сбросилось 15 минутами раньше,
   а не «расхода нет». Точка с `p = 0` в систему не входит по порогу; трактовать
   её как «лимит пуст» в UI можно, как «наш расчёт неверен» — нельзя.
4. **Кэш обязан жить в main, а не в ядре.** В ядре он оказался бы у каждого
   вызывающего свой, и попап с окном сходили бы порознь. В `limits/oauth.ts`
   лежат чистые функции (разбор, решение про `Retry-After`, состояние окна
   backoff), сам вызов и таймеры — в `main/oauth.ts`.
5. **Ошибка сети — это не «лимит неизвестен».** Отвалившийся запрос не должен
   стирать последний удачный снимок с экрана: показывается прежний с его
   возрастом, а не пустота. Возраст обязан быть виден — снимок часовой давности
   и снимок минутной давности выглядят одинаково, пока не написано, который из
   них какой.
6. **`User-Agent` подделывать не нужно.** Ответ 200 приходит и на
   `User-Agent: Agentmeter`; притворяться `claude-code/<version>`, как записано
   в пункте 4 брифа 1.9, не требуется — и не будем: врать провайдеру о том, кто
   стучится, ради продукта про честность цифр.
7. **README обещает «ровно один сетевой вызов».** Обещание правится в том же
   коммите, что и код, а не «потом». Формулировка: два вызова, оба выключаемые,
   второй — выключен по умолчанию.
