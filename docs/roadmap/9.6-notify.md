# 9.6 — Уведомление «пора в /retro»

**Кто:** sonnet, high · **Объём:** S · **Блокирует:** —

Порог вместо расписания. Разбор логов моделью стоит токенов, а за день
набирается шум, поэтому повод для разбора — пересечённый порог пользователя, а
не полночь. Если этап сделать плохо, уведомление будет приходить на каждом
снимке или ни разу.

## Файлы

```
править:    apps/desktop/src/main/notify.ts      (planNotifications :74, по образцу limitNotices)
            apps/desktop/src/main/snapshot.ts    (latest-показатели workflow в снимке, только при enabled)
            apps/desktop/test/notify.test.ts
            packages/core/src/i18n/{ru,en}.ts
не трогать: packages/core/src/query/workflow.ts
```

## Контракт

- Показатели `rework`, `errorRate`, `overhead` из `latest` окна. Порог —
  `config.workflow.alerts.*`, `null` выключает показатель.
- Ключ `Notice` — `workflow:<metric>:<id последнего цикла окна>`. Новое окно —
  новый повод, то же окно — тишина.
- Первый снимок только запоминает (`seeded`), как у остальных уведомлений.
- В тексте показатель, значение и порог. Слова «плохо» нет: «Доля переделки
  46% — выше вашего порога 30%. Повод разобрать логи: /retro».

## Критерий готовности

```bash
npm run typecheck && npm run lint && npm test -w @agentmeter/desktop -- notify
```

Кейсы: ниже порога — тишина; пересёк — одно уведомление; следующий снимок того
же окна — тишина; новое окно выше порога — снова; `null` — никогда; workflow
выключен — никогда.
