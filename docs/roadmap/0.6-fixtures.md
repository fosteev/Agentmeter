# 0.6 — Фикстуры

**Кто:** сам · **Объём:** L · **Блокирует:** 1.1, 1.2, 1.3, 1.5, 1.6 — то есть весь M1

Восемь обрезанных и обезличенных кусков реальных логов плюс ожидаемый разбор
к каждому. Делаю сам и первыми: если отдать парсер без эталонных данных,
исполнитель придумает формат по описанию и отрапортует, что всё сходится.

## Файлы

```
создать:  fixtures/claude/<сценарий>.jsonl
          fixtures/claude/<сценарий>.expected.json
          fixtures/codex/<сценарий>.jsonl
          fixtures/codex/<сценарий>.expected.json
          fixtures/ground-truth.json
          scripts/make-fixtures.ts
```

`make-fixtures.ts` — не одноразовый скрипт, а инструмент: логи будут меняться
с версиями CLI, фикстуры придётся пересобирать.

## Восемь сценариев

| сценарий | что проверяет | где брать |
|---|---|---|
| `plain` | обычная сессия, один тул за ход | любая короткая сессия |
| `sidechain` | сабагенты, `isSidechain: true` | сессия с вызовом Task |
| `mcp` | `mcp__server__tool`, имена и серверы | сессии в `pilot` — там jira и wiki |
| `compact` | скачок префикса при сжатии контекста | длинная сессия, > 200 запросов |
| `images` | тул вернул картинку, base64 в лог не попал | сессии с mobile-mcp или Read по png |
| `parallel` | несколько тул-коллов в одном ходе — дележ дельты | искать ходы с 2+ `tool_use` |
| `codex` | роллаут с `token_count` и заполненным `rate_limits` | `~/.codex/sessions/2026/07/13/` |
| `versions` | три разные версии CLI в одном наборе | 2.1.220, 2.1.223, 2.1.226 — все есть на диске |

## Обезличивание

Фикстуры поедут в репозиторий, поэтому из них вычищается всё, кроме структуры:

- тексты промптов и ответов → заглушки той же длины (длина влияет на дележ дельты,
  поэтому её надо сохранить);
- пути → `/proj/a`, `/proj/b`, домашний каталог → `~`;
- имена файлов, ветки, ключи тикетов → синтетические;
- **`usage`, `requestId`, `timestamp`, имена тулов и серверов не трогать вообще** —
  это и есть предмет разбора.

Проверка: `grep` по фикстурам не находит ни одного реального пути, имени
проекта или куска переписки.

## `ground-truth.json` — отдельно и важнее всех

Слепок эталонных сумм из `~/.claude.json`: по каждому проекту `lastSessionId`
и его `lastModelUsage` с разбивкой по моделям. На момент разведки — 41 проект,
из них 16 с сессиями, файлы которых лежат на диске.

Это единственный независимый источник правды: цифры посчитаны самим Claude Code,
а не мной из тех же данных. На нём стоит этап 1.3.

Слепок снимается один раз и коммитится: `.claude.json` перезаписывается при
каждом запуске, эталон нужен воспроизводимый.

## Критерий готовности

```bash
npm run fixtures:check
```

Проверяет: все восемь сценариев на месте, каждый парсится как JSONL без
исключений, `.expected.json` есть к каждому, обезличивание прошло
(нет реальных путей), `ground-truth.json` содержит ≥ 15 сверяемых сессий.

## Подводные камни

- **Обрезать сессию посередине нельзя произвольно.** Маржинальная атрибуция
  считает дельту между соседними запросами — если вырезать середину, дельта на
  шве станет мусором. Резать только по границам ходов, целыми парами
  «ассистент + результаты тулов».
- **`requestId` не уникален построчно.** Один ответ API пишется несколькими
  строками `assistant` с одним `requestId` и продублированным `usage`. Наивная
  сумма по строкам завысит расход в разы, наивный дедуп по первой строке —
  занижает (см. 1.3). Фикстура `plain` обязана содержать такой случай.
- **Размер результата в логе не равен тому, что ушло в промпт.** На реальном
  `Read` в логе лежало 382 КБ, а в промпт попало 2873 токена. Фикстура `images`
  и `plain` должны сохранить это расхождение, иначе 1.6 «сойдётся» на неверной
  модели.
