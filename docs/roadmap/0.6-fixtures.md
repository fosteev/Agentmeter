# 0.6 — Фикстуры

**Кто:** сам · **Объём:** L · **Блокирует:** 1.1, 1.2, 1.3, 1.5, 1.6 — то есть весь M1

Обрезанные и обезличенные куски реальных логов плюс ожидаемый разбор к каждому.
Делаю сам и первыми: если отдать парсер без эталонных данных, исполнитель
придумает формат по описанию и отрапортует, что всё сходится.

## Файлы

```
fixtures/claude/<сценарий>.jsonl           обезличенный лог
fixtures/claude/<сценарий>.expected.json   ожидаемый разбор
fixtures/claude/sidechain.subagents/       транскрипты сабагентов
fixtures/codex/rollout.jsonl
fixtures/ground-truth.json                 эталон Claude Code, только читать
scripts/make-fixtures.ts                   пересборка
scripts/check-fixtures.ts                  проверка
scripts/fixtures.config.json               источники и что каждая проверяет
```

`make-fixtures.ts` — не одноразовый скрипт, а инструмент: логи меняются с
версиями CLI, фикстуры придётся пересобирать.

```bash
npm run fixtures         # пересобрать из живых логов
npm run fixtures:check   # проверить
```

## Обезличивание

Правило одно: всё, что не структурный ключ, — текст, и он заменяется заглушкой
**той же длины**. Длина важна: на ней стоит дележ дельты между параллельными
вызовами, и фикстура с укороченными текстами тихо сломает атрибуцию (1.6).

Не трогается вообще: `usage`, `requestId`, `timestamp`, имена тулов и MCP-
серверов, версии CLI, флаги. Это и есть предмет разбора. Пути превращаются в
`/proj/a`, ветки в `feature/one`, uuid — в детерминированные подделки того же
вида (связность `parentUuid` → `uuid` сохраняется).

`check-fixtures.ts` ищет в результате следы живых данных регулярками и падает,
если что-то просочилось.

## `ground-truth.json`

Слепок из `~/.claude.json`: по каждому проекту `lastSessionId`, итоги и
разбивка по моделям. 42 проекта. Имена проектов — псевдонимы, id сессий
настоящие: по ним `verify` находит файлы на диске.

Снят один раз и закоммичен. Пересъёмка обесценивает сверку: `.claude.json`
перезаписывается при каждом запуске CLI, а эталон нужен воспроизводимый.

## Что выяснилось по ходу

- **Резать сессии не понадобилось.** Нашлись целые сессии подходящего размера,
  а целая сессия честнее обрезанной: дельта на шве не превращается в мусор.
- **`requestId` не уникален построчно, и строки не одинаковы.** `output_tokens`
  в ранних строках частичный — стриминг наращивает его по ходу ответа.
  Схлопывать надо максимумом по каждому полю (см. 1.3).
- **Ожидаемый разбор строится не парсером из `core`**, а отдельной реализацией
  в `make-fixtures.ts` — иначе фикстура подтверждала бы сама себя.

## Критерий готовности

```bash
npm run fixtures:check
```

Проверяет, что все сценарии на месте, парсятся как JSONL, к каждому есть
`.expected.json`, обезличивание прошло — и, главное, что каждая фикстура
содержит именно тот сценарий, ради которого её брали. Фикстура `parallel` без
единого параллельного вызова зелёная по формальным признакам и бесполезна по
существу.
