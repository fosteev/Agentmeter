# 1.4 — Устойчивость к дрейфу формата

**Кто:** сам · **Объём:** M · **Блокирует:** 1.5 (индекс не должен вставать на
незнакомом файле) · **Ждёт:** 1.1, 1.2 — оба готовы

Фикстуры проверяют, что парсер понимает восемь отобранных сессий. Этот этап
проверяет обратное: что он не падает на всём остальном — 590 транскриптах
Claude за 24 версии CLI и 329 роллаутах Codex за 36 версий. Формат меняется
каждую неделю, и вопрос не в том, появится ли незнакомая запись, а в том, что
случится, когда она появится: тихо уедет в диагностику или уронит индексацию
на первом же файле.

## Чем проверяется

```bash
node --experimental-strip-types scripts/probe/drift-scan.ts   # Claude
node --experimental-strip-types scripts/probe/codex-live.ts   # Codex
```

Оба скрипта — зародыш `doctor` (1.10): перечисляют незнакомые типы записей с
версиями CLI, где они встретились, считают ломаные строки и файлы, уронившие
разбор. `codex-live.ts` вдобавок гоняет встроенную в формат сверку сумм.

Ненулевой код возврата = что-то упало или не сошлось.

## Что нашлось по дороге

Три находки, и все три меняли цифры, а не только диагностику.

### 1. Codex пишет `token_count` дважды на один запрос

174 сессии из 311. Две записи подряд с одинаковым `last_token_usage`, между
ними накопительный итог не двигается. Наивный подсчёт завышал расход **почти
вдвое** — и при этом выглядел совершенно здоровым: тест на фикстуре зелёный,
исключений нет, цифры правдоподобные.

Признак повтора — неподвижный `total_token_usage`: у настоящего запроса он
сдвигается ровно на `last_token_usage`. После дедупликации по этому правилу
сумма сходится с итогом до токена во всех 311 сессиях, где расход вообще есть.

Это тот же класс ошибки, что `requestId` у Claude (пункт 3 в `CLAUDE.md`):
формат пишет одну сущность несколькими записями, а суммирование по записям
завышает в разы. Ловится только сверкой с независимым итогом, поэтому такая
сверка обязана быть отдельным тестом в каждом парсере, где источник её
позволяет.

### 2. Сабагенты воркфлоу лежат на уровень глубже

`parseSubagents` читал только `<sessionId>/subagents/*.jsonl`. У воркфлоу
транскрипты уходят в `subagents/workflows/wf_<id>/agent-<id>.jsonl` — таких
файлов на диске **220 против 150** обычных, то есть больше половины расхода
сабагентов не читалось вовсе. Обход сделан рекурсивным, отбор — по префиксу
`agent-`.

Рядом с ними лежит `journal.jsonl` — журнал воркфлоу со своим словарём записей
(`started`, `result`) и без единой цифры расхода. Это не транскрипт: разбирать
его как сессию значит завести в индексе фантомную сессию без запросов. Отбор по
префиксу `agent-` отсекает его без чтения содержимого; **1.5 обязан
пользоваться тем же правилом**, а не `**/*.jsonl`.

### 3. Сигнал компакта у Codex всё-таки есть

В брифе 1.2 записано, что его нет, — потому что в фикстуре его нет. На диске он
есть: `compacted` верхним типом плюс `event_msg/context_compacted`, парой с
одним timestamp, 35 раз в 19 сессиях. Следующий после него запрос помечается
`compacted: true`.

Мелочи из того же прогона: `custom-title` у Claude (482 записи в 42 файлах) —
название сессии, вбитое руками, важнее сочинённого `ai-title`;
`thread_name_updated` у Codex — то же самое; `web_search_end` — единственная
запись веб-поиска, несущая `call_id`, поэтому поиск заводится по ней, а не по
`web_search_call`, который в 383 случаях из 391 пишется без идентификатора.

## Правило на будущее

Парсер знает конечный список типов записей. Всё, чего в списке нет, попадает в
`diagnostics.unknownRecordTypes` вместе с версией CLI и **никогда** не роняет
разбор. Пустой список незнакомых типов сегодня — не повод его не вести: он
опустеет ровно до следующего обновления CLI.

Обратное тоже верно: незнакомый тип в диагностике — не «ошибка парсера», а
сигнал сходить и посмотреть, не появилось ли в формате чего-то, что меняет
цифры. Из трёх находок выше две пришли именно оттуда.

## Что осталось

* Фикстуры Codex с дубликатом `token_count` и с компактом. Сейчас оба случая
  закрыты юнит-тестом на синтетическом файле и прогоном по живым роллаутам;
  фикстуры из реального лога были бы надёжнее.
* `doctor` (1.10) должен показывать то же, что показывают эти два скрипта.
