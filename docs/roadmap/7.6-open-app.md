# 7.6 — Клик по уведомлению открывает программу агента

**Кто:** сам · **Объём:** S · **Блокирует:** ничего

Уведомление «Claude закончил — Agentmeter» отвечает на один вопрос: пора
вернуться к работе. Возвращаться человек хочет в редактор, где эта работа
лежит, а не в счётчик токенов, — а клик до 7.6 открывал именно счётчик. Сделать
плохо здесь легко и незаметно: программу можно «определить» по `entrypoint` из
файла сессии, и на машине с VS Code это даже сработает. У человека с Cursor тот
же код молча откроет чужой редактор, а уведомление, иногда поднимающее не то
окно, перестают трогать вовсе.

## Что измерено

**Программу даёт цепочка `ppid`, и только она.** В файле сессии
(`~/.claude/sessions/<pid>.json`) лежит `entrypoint`, и у VS Code, Cursor и
Windsurf он одинаковый — `claude-vscode`. Настоящее приложение — первый бандл
вверх по родителям, три прыжка на живой машине:

```
28496 claude                                             (процесс агента)
12103 Cursor Helper (Plugin): extension-host (user) Agentmeter [1-1]
11691 /Applications/Cursor.app/Contents/MacOS/Cursor      (бандл)
```

Замер пробой: **19 живых сессий из 19** дошли до бандла, включая сессию
JetBrains ACP (`entrypoint: sdk`) — у неё владелец `PhpStorm.app`.

**До окна цепочка не доводит, и это граница, а не недоделка.** Хост расширений
один на окно, но какое это окно — не спросить: 19 сессий висели на трёх хостах,
шесть из них на одном (`Agentmeter [1-1]`). Указателя на чат внутри окна нет ни
в реестре, ни в транскрипте, поэтому этап и называется «программу», а не «окно».

**Бандл берётся внешний, а не ближайший.** Хелперы Electron лежат внутри бандла
своего приложения (`Cursor.app/Contents/Frameworks/Cursor Helper (Plugin).app/…`),
и поиск последнего `.app` в пути выдаёт имя, которого нет ни в Dock, ни в
`open -a`. Берётся первый `.app` в пути.

**Узнавать надо, пока агент жив.** `done` в снимке означает, что процесса уже
нет ([`live/state.ts`](../../packages/core/src/live/state.ts) — `if (!input.alive) return 'done'`),
то есть в момент самого нужного уведомления спрашивать `ps` поздно. Владелец
запоминается, как только сессия впервые появилась в снимке, и переживает её
смерть.

## Чего этап не делает

- **Не поднимает конкретное окно.** `open -a` активирует приложение, дальше
  выбирает оно само. Точный подъём окна — `AXRaise` по заголовку — требует
  разрешения «Универсальный доступ», а оно привязано к подписи, которой у
  проекта нет (5.2). Функция, отваливающаяся после каждой пересборки, хуже её
  отсутствия — то же правило, что у кнопок в уведомлении (4.7).
- **Не работает у Codex.** Реестра процессов у него нет вовсе (пункт 9 в
  `CLAUDE.md`), а процесс из расширения IDE держит `cwd` равным `/` (замерено на
  двух живых процессах) — связи «сессия → процесс» не существует.
- **Не работает на Windows и Linux.** `ownerApps` там возвращает пустую карту:
  поднять чужое окно на Wayland композитор не даёт вовсе, на Windows мешает
  foreground lock. Клик открывает наше окно, как раньше.
- **Не добавляет настройку.** Тумблер «уведомления об агентах» уже есть
  (`alerts.notifyOnIdle`), а второй — «куда открывать» — это вопрос, ответ на
  который у всех один.

## Контракт

`Notice.sessionId` есть у поводов об агенте и о дорогой сессии, и его нет у
поводов о лимите: процент считается по аккаунту, а не по чату, и открывать по
нему чей-то редактор не за что.

`OwnerBook.reveal` возвращает `false`, когда программа неизвестна **или** когда
`open` отказал, — и тогда зовущий открывает своё окно. Отказ, выданный за успех,
даёт клик, не приводящий никуда.

Владельцы читаются из реестра внутри `owner.ts`, а не из `TraySnapshot`: `pid` —
деталь процесса, и класть его в контракт main↔renderer ради одного клика значило
бы завести в нём поле, которое окну не нужно.

## Критерий готовности

```bash
npm test -w packages/core -- process

node --experimental-strip-types scripts/probe/owner-live.ts
npm run check
```

## Данные

Живое дерево процессов: `ps -Ao pid=,ppid=,comm=` плюс `~/.claude/sessions/`.
Фикстуры здесь не заводятся — дерево у каждого своё, и эталон из него получился
бы про одну машину. В юнит-тесте лежит выписка из живой таблицы (шесть строк,
`packages/core/test/live/process.test.ts`), в пробе — вся таблица целиком.

## Подводные камни

- Заголовок процесса у хелперов Electron содержит пробелы, скобки и квадратные
  скобки (`Cursor Helper (Plugin): extension-host (user) Agentmeter [1-1]`) —
  разбор сплитом по пробелам его режет.
- `ppid` приезжает от ОС, процессы между строками таблицы умирают и рождаются
  заново: кольцо в родителях повесило бы опрос трея, а с ним и всё приложение.
  Отсюда потолок глубины.
- `learn` зовётся раз в секунду. Без отсечения уже известных сессий это чтение
  каталога и запуск `ps` ежесекундно ради неизменного ответа; неудача
  запоминается наравне с удачей, иначе каждая сессия Codex делает то же самое.
