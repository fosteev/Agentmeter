# 9.4 — Макет: раздел 13 «Workflow»

**Кто:** opus · **Объём:** M · **Блокирует:** 9.5

Новый экран без прототипа — это всегда сильная модель (правило делегирования),
поэтому сначала макет в полотне. Его сдвинет только замер. Прототип смысла, но не
вида, уже есть: дашборд discovery (claude.ai, «Маршруты агентов»). Он доказал
порядок чтения: главный показатель → график по циклам → три контрольных → роли
→ подробности.

## Что нарисовать

- Главный показатель: доля переделки последнего окна крупно, дельта к окну до
  него, подпись «последние N циклов, по <дата>». Цель — пунктир, только если
  задана.
- График: ось X — номер цикла (подпись — дата), ось Y — доля. Наведение
  показывает цикл, проект, правки по ролям.
- Три контрольных с маленькими линиями: накладные (×, токены), ошибки
  инструментов (%), вердикты (доля «не принят» и «с оговорками»).
- Разбивка по ролям: расход и правки, строка `unknown` видна всегда. Отдельно —
  кто переделывает после исполнителя: главная сессия (`/plan-review`) или
  ревьюер-агент (`afterByRole` из 9.3).
- Пустые состояния: «окно не набралось (N из 10)», «Workflow выключен» и «ни
  одного исполнителя по вашим правилам» со ссылкой на настройки.
- Подвал: правки через шелл не видны, накладные в токенах, а не в деньгах.
- Раздел настроек «Workflow»: таблица правил ролей, три регулярки вердикта,
  окно, цель, пороги.

**По реальному коду (9.3, 25 октября).** Что `workflowReport` отдаёт под каждый блок
(полная форма — «Решения» в [`9.3-report.md`](9.3-report.md)):

- **Главный показатель** — `rework.latest.value`, `rework.delta` (разность долей, показывать в п.п.),
  подпись «последние N циклов, по <дата>» — `rework.size` и `latest.startedAt` (старт
  последнего цикла окна). Цель — `config.workflow.target.rework` (доля 0..1, `null` — линии нет).
- **График** — `rework.points`: **одна точка на полное окно**, поэтому ось X начинается с
  цикла номер `size`, а не с первого (12 циклов при N = 5 — 8 точек). Точка знает `n`
  (номер цикла) и `startedAt`; подсказка по ней — `cycles[n − 1]`: проект, `writes` и
  `writesAfter` по ролям, вердикты ревьюеров.
- **Три контрольных.** Накладные — `overhead` (кратность; `≈` на точке, где `approximate`).
  Ошибки — `errorRate`: **ряд по сессиям, не по циклам**, ось X — порядок сессий, а точек
  на живом индексе 1 369 — рисовать нужно последние 40–60. Вердикты — `verdicts`: точка
  несёт `value` — долю «с оговорками + не принят» среди вердиктов (принят + с оговорками +
  не принят) — и счётчики `counts` всех четырёх вердиктов; «вердикта нет» в долю не входит.
- **Роли** — `roles`: суммы расхода, записей и `afterByRole` за последние `min(N, число
  циклов)` циклов (`roles.cycles` — сколько вошло); шесть строк всегда — `main`, `executor`,
  `reviewer`, `planner`, `explore`, `unknown` (последняя видна и когда в ней ноль).
  Доли считает main. `main` — «главная сессия», подписи для него в каталогах нет.
- **Пустых состояний пять, а не три:** «Workflow выключен» (конфиг), «индекс не собран»
  (`emptyIndex`), «ни одного исполнителя по вашим правилам» (`cycles.length === 0 &&
  !emptyScope`), **«фильтр отсёк всё»** (`emptyScope` — циклы в индексе есть, но не в этом
  проекте; в списке выше его не было), «окно не набралось (`count` из `size`)» (`points` пуст,
  `latest = null`). И два «дельты нет»: нет окна перед последним (нужно не меньше `2·size`
  циклов, а при нулевом знаменателе и больше) и нулевой знаменатель (точки нет, а не нуль).
- **Невидимый исполнитель — решено в приёмке 9.3, макету рисовать.** В 4 из 7 живых циклов
  исполнители не оставили **ни одной** видимой записи (пишут шеллом: `python3 - <<'EOF'`,
  `sed -i`; MCP-правки не видны тоже — правило 14), а ревьюер и главная сессия правят
  `Edit`-ом; такой цикл давал переделку 100%. Теперь он **из переделки исключён**:
  `cycles[].executorUnseen`, у точки переделки — `unseen` (сколько циклов окна исключено),
  у ролей — `roles.unseen`. Окно остаётся «последние N циклов», доля — по циклам с видимым
  исполнителем, и **рядом с главным числом обязана стоять строка** вида «по 2 циклам из 3:
  в 1 исполнитель правил шеллом — правок не видно» (`latest.unseen`, `rework.size`); все
  исключены — точки нет, состояние то же, что «нулевой знаменатель». В подсказке точки
  графика у такого цикла — пометка вместо «0 / after». Частичная невидимость остаётся
  подвалом, и она большая: шеллом идёт примерно пять правок из шести у всех ролей
  (правило 31) — подвал говорит «считаются только правки `Edit`/`Write`; правки шеллом и
  MCP не видны», а не «бывают исключения». `≈` у переделки не ставится — `approximate` у
  неё всегда `false`.
- **`≈` — только у накладных** (`overhead.points[].approximate`); у переделки, ошибок и
  вердиктов флаг всегда `false`.
- **«Роль не определена» внутри циклов мала.** 663 из 871 сабагента без роли
  (`general-purpose` 583, `workflow-subagent` 81) — почти все **вне** циклов: в деревьях семи
  циклов 118 сабагентов, из них без роли 8 (`general-purpose`), их расход — 3.3% всех циклов
  и 6.4% окна 3, записей ноль. Строку `unknown` показывать всегда, но это строка, а не
  главный блок: долей задавить экран ей не из чего. Число «663 из 871» — для доктора, не
  для экрана.
- **Живые числа для макета** (проба `workflow-live.ts`, приёмка 25 октября, свежий индекс
  из логов; два последних цикла — сегодняшние сессии, их числа ещё растут). Без правок
  конфига окно 10: циклов **7** (6–25 октября) — состояние «окно не набралось (7 из 10)»;
  ошибки (окно 20 сессий) 1.6% (14 из 868 известных вызовов), окно до него 0.0% (0 из 227).
  Чтобы нарисовать главный вид, окно 3:

  | показатель | последнее окно | окно перед ним | дельта |
  | --- | --- | --- | --- |
  | переделка | 23.1% (6/26), исключён 1 цикл | 29.4% (5/17), исключено 2 | −6.3 п.п. |
  | накладные | ×0.45 | ×7.09 `≈` | −6.63 |
  | вердикты, «с оговорками + не принят» | 87.5% (принят 1, с оговорками 7, не принят 0, нет 1) | 27.3% | |
  | ошибки, окно 20 сессий | 1.6% (14/868) | 0.0% (0/227) | +1.6 п.п. |

  Ряд переделки (`n`: значение) — 4: 29.4%, 5: 34.6%, 6: 25.6%, 7: 23.1% (точки `n = 3` нет:
  все три первых цикла с невидимым исполнителем); накладных — 3: ×5.27, 4: ×7.09, 5: ×8.25,
  6: ×0.74, 7: ×0.45. Роли окна 3 (`roles.unseen = 1`): расход main 26.9M (11.4%), executor
  144.5M (61.4%), reviewer 38.6M (16.4%), planner 10.0M (4.3%), explore 0, unknown 15.1M
  (6.4%); записи main 3 (после старта 1), executor 20, reviewer 5 (после 5), planner 10
  (после 0). За все семь циклов по видимым: записей исполнителей 32, `after` 11 → 25.6%
  (без исключения было бы 49.2%; только ревьюер-агенты, как у discovery, — 39.6%, у него
  42%). Подсказки графика — семь циклов (дата · проект · записи исполнителя / `after` по
  ролям · накладные):

  | № | дата | проект | исполнитель / `after` | накладные |

  | 1 | 6 окт | pilot | невидим / 5 (главная 1, ревьюер 2, планировщик 2) | ×7.21 |

  | 3 | 6 окт | pulse | невидим / 15 (главная 1, ревьюер 14) | ×6.15 `≈` |
  | 4 | 9 окт | at | 12 / 5 (главная 5) | ×14.09 `≈` |

- **Единица окна ошибок — сессия** (корень или сабагент по отдельности), как в брифе 9.3; на
  живых данных 20 сессий — около шести часов работы. Менять ли её на задачу (корень с
  деревом) — решение макета, цена — одна функция в ядре (см. «Скоуп» в 9.3).
