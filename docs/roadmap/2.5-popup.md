# 2.5 — Попап 400×600 на живых данных

**Кто:** Codex · **Объём:** M по вёрстке, L по факту · **Блокирует:** 2.6, 2.7,
2.8 и весь M3 (окно строится на этой же обвязке)

Название этапа обманывает. Вёрстка попапа — меньшая его часть: попап собран из
компонентов, которые уже сделаны в 2.4, и по макету он складывается почти без
новой раскладки. Настоящее содержание этапа в другом: **Electron в проекте не
поднят вообще.**

Сегодня в `apps/desktop/` лежит только рендерер: `tokens.css`, четыре
компонента, витрина `gallery.tsx` и числовой тест приёмки. Нет main-процесса,
нет окна, нет бандлера, нет точки монтирования — витрину буквально негде
посмотреть, она не отрендерена ни разу. Пакета `electron` нет ни в одном
`package.json`. Контракт IPC (`packages/ipc`, этап 0.4) написан в M0, полностью
типизирован и **не исполнялся ни разу**.

Поэтому порядок работ здесь обратный ожидаемому: сначала приложение
запускается и показывает пустое окно, потом в окно приезжают живые данные,
и только потом это красится по макету. Если начать с вёрстки, обвязка будет
доделываться в последний день, а она — единственная часть этапа, где ошибка
стоит дорого и всплывает на чужой ОС.

Что ломается при плохом исполнении: приложение, которое не запускается на
второй платформе (нативный модуль, пути, ESM); рендерер, который сам считает
токены и потому расходится с CLI на той же машине; и незнание, показанное
нулём, — Claude до этапа 1.9 не имеет процента лимита вовсе, и попап обязан это
показать, а не нарисовать пустую полосу.

## Часть 0. Проверить до первой строки кода

Ядро работает на встроенном `node:sqlite` (`packages/core/src/index/db.ts`) —
выбран ради того, чтобы не тащить `electron-rebuild` в упаковку (M5). Есть ли
он в main-процессе Electron — **вопрос факта, а не веры**.

Первым делом: минимальный main, который делает `new DatabaseSync(':memory:')`,
создаёт таблицу и выходит с кодом 0. Локально Node 22.15 открывает базу без
флага (проверено), Electron несёт свою сборку Node — сверить надо именно её.

Если не работает — **остановиться и сообщить, не выбирая замену самостоятельно.**
Уход на `better-sqlite3` меняет упаковку на трёх платформах и открытый вопрос
из роадмапа, это не решение исполнителя. То же про любую попытку прокинуть
`--experimental-sqlite` через `NODE_OPTIONS` или `app.commandLine`: сначала
сообщить, что понадобился флаг.

## Часть 1. Electron поднимается

Минимальный, но полный каркас. Ничего сверх перечисленного не заводить —
автообновление, меню, вторые окна и настройки это M3 и M5.

**Main-процесс.** `apps/desktop/src/main/`: создание окна, открытие индекса
(`openDb`), запуск вотчера (`watchSources`), живой слой из 2.1, регистрация
обработчиков IPC, таймер опроса. Собирается тем же `tsc`, что и весь репозиторий
(ESM, `"type": "module"`), бандлером **не** прогоняется: main обязан остаться
обычным Node-кодом, иначе `node:sqlite` и пути к домашним каталогам придётся
чинить настройками бандлера.

**Preload.** `apps/desktop/src/preload/`. `contextIsolation: true`,
`nodeIntegration: false`, `sandbox: true`. Наружу выставляется один типизированный
объект, собранный по спискам `IPC_CALLS` и `IPC_EVENTS` из контракта.

**Бандлер — только для рендерера.** Vite: ему нужно собрать React, `tokens.css`
и шесть `woff2`. Выход — статические файлы, окно грузит их с `file://`.

**Две точки монтирования, обе обязательны:**

- `index.html` + `main.tsx` — попап;
- `gallery.html` — та самая витрина 2.4, которую пока негде посмотреть. Она
  не выбрасывается и не переезжает в попап: это спецификация компонентов, и
  после этапа на неё наконец можно смотреть (`npm run -w @agentmeter/desktop gallery`).

**Трей — заглушка, и это осознанно.** Попап открывается по клику в трее, а
иконка трея — этап 2.7. Поэтому здесь создаётся `Tray` с временной иконкой
(один сплошной квадрат 16×16 цвета `--claude`, сгенерированный в коде через
`nativeImage.createFromBuffer`), чтобы попапу было откуда открываться. Рисовать
пять состояний, template image для macOS и цветную для Windows — **не в этом
этапе**. Отдельной командой `npm run -w @agentmeter/desktop dev` попап должен
открываться и без трея, обычным окном: иначе разработка упирается в трей на
каждой платформе.

**Позиционирование.** macOS — попап под иконкой menu bar, с хвостиком
(строка 453 макета). Windows и Linux — то же окно без хвостика, прижато к трею.
Координаты из `tray.getBounds()`, размер экрана из `screen`. Различие ровно
одно, дублировать раскладку под платформу нельзя.

## Часть 2. Проводка через `packages/ipc`

Контракт готов и меняться не может. Что делает этап:

- в main регистрируются обработчики **на все** имена из `IPC_CALLS`. Те, чьи
  данные появятся в M3 (`today:list`, `task:get`, `breakdown:get`,
  `config:set`, `index:rebuild`, `doctor:get`, `window:open`), реализуются
  честной заглушкой — обработчик есть, отдаёт пустой результат нужного типа.
  Незарегистрированный канал даёт в рендерере повисший `invoke`, и это худшая
  из возможных заглушек;
- в рендерере **нет ни одного строкового литерала канала**. Клиент строится по
  спискам из контракта, вызовы типизированы;
- `snapshot:get` и событие `live:update` наполняются по-настоящему: живой слой
  (2.1) → `TraySnapshot`. Период опроса при открытом попапе — `config.live.pollMs`
  (по умолчанию 1000 мс; на этом числе держится критерий 2.1 «новая сессия видна
  < 2 с», трогать его в коде нельзя). При закрытом попапе опрос реже — пятикратный
  множитель прямо в main, в конфиг его не выносить, пока не понадобится;
- **рендерер не считает.** Правило записано в шапке контракта: наружу уезжают
  готовые к показу числа и признак точности. Никакой арифметики над токенами в
  компонентах попапа — иначе та же цифра посчитана дважды и разойдётся с CLI.

`apps/desktop/tsconfig.json` сейчас ссылается только на `packages/core` —
добавить ссылку на `packages/ipc`. Рендерер импортирует из `@agentmeter/core`
**только типы** (`import type`): значение потянет `node:sqlite` в браузерный
бандл.

## Часть 4. Долг: формат чисел берёт локаль

Сейчас форматтеров два: `apps/cli/src/format.ts` (принимает `locale`) и
`apps/desktop/src/renderer/format.ts` (зашитый `en-US`, суффикс `k`). На одной
машине CLI и попап покажут разные числа — ровно то, чего измерительный продукт
позволить себе не может.

Один форматтер на всех: `packages/core/src/format/tokens.ts`, обе точки входа
зовут его и передают `config.ui.locale`. Суффикс тысяч — строчный `k`, как в
макете (`38k`, `14.8k`); CLI приводится к макету, а не наоборот, потому что
эталон здесь макет.

**Следствие, которое надо принять сознательно:** при локали `ru` (дефолт
конфига) попап покажет `344,9M` там, где в макете нарисовано `344.9M`.
Разделитель приходит из локали — это правильное поведение, макет рисовался до
появления локали в конфиге. Макет **не править**, число в тесте ожидать по
локали теста.

## Контракт

- **IPC** — `packages/ipc/src/index.ts`. Имена каналов, типы аргументов и
  ответов заданы. Канала, которого нет в `IPC_CALLS`/`IPC_EVENTS`, не
  существует; добавить свой нельзя. Контракт доведён под этот этап заранее — в
  `TraySnapshot` появился `at` (момент снимка, от него считаются все
  длительности), в `LiveAgent` — `endedAt` и `approximate`, в `DayTotals` —
  `projects`. Если чего-то всё-таки не хватает: **остановиться и сообщить**,
  контракт правит владелец M0, а не исполнитель этапа.

  Так и вышло: первый исполнитель этапа остановился здесь, и по делу. Довод
  «рендерер не считает» упирался в три дырки, все три — недосмотр владельца.
  `DayTotals` не давал готовой суммы, и число в подвале («344.9M») пришлось бы
  складывать в окне из четырёх полей, выводя пятую точность из четырёх.
  А `TraySnapshot.limits` был объявлен голым `LimitWindow[]` и терял оба поля,
  которые `limitsReport` уже считает: `unavailableReason` — без него окно
  Claude без процента показывать нечем, кроме пустой полосы, то есть проверка
  2 критерия была невыполнима в принципе, — и `forecast`, то есть вторую
  половину 2.3. Исправлено: `DayTotals.total`, `limits: LimitReportRow[]`,
  тот же тип у `limits:get`. Фикстура повторяла ту же ошибку и обновлена
  вместе с контрактом, `packages/ipc/test/fixture.test.ts` теперь пинит и
  сходимость суммы, и наличие причины у окна без процента.

- **Данные попапа** — `TraySnapshot` оттуда же: `agents`, `limits`, `today`,
  `nearestLimitPercent`, `indexing`.
- **Точность** — `Measured.confidence` (`exact | reconstructed | estimate`) и
  `LimitWindow.exact`. Отображение задано макетом и разобрано в
  `docs/roadmap/design-implementation.md`: сплошная заливка против штриховки
  плюс знак `≈`. Подписей-дисклеймеров нет нигде — это решение дизайна.
- **Токены и компоненты** — `apps/desktop/src/renderer/tokens.css` и четыре
  компонента из 2.4. Значения `:root` перенесены из макета посимвольно и
  сверяются тестом.
- **Конфиг** — `packages/core/src/config/types.ts`, контракт 0.5. Читается
  через `loadConfig`, из него берутся `ui.theme` и `ui.locale`.

## Критерий готовности

```bash
npm run check
npm run -w @agentmeter/desktop build
node --experimental-strip-types scripts/probe/desktop-smoke.ts
```

Смоук запускает собранное приложение с флагом `--smoke`: main открывает индекс,
собирает `TraySnapshot`, печатает его JSON и выходит с кодом 0, окна не
показывая. Это единственная проверка, которая доказывает, что Electron вообще
живой и `node:sqlite` в нём работает; без неё «зелёный `npm run check`» ничего
про приложение не говорит.

Автотесты — шесть проверок. Каждая названа по поломке, которую обязана поймать:

1. **Все каналы контракта обслуживаются.** Множество зарегистрированных в main
   обработчиков совпадает с `IPC_CALLS` точно, в обе стороны; то же для
   `IPC_EVENTS` и клиента из preload.
   _Ловит:_ канал, добавленный строкой мимо контракта (в рендерере повиснет
   `invoke` без ответа), и обработчик, потерянный при переименовании.
2. **Незнание не показано нулём.** На снимке, где у окна Claude
   `usedPercent === null`, в разметке нет ни `0%`, ни полосы с ненулевой
   шириной, а причина недоступности выведена текстом.
   _Ловит:_ единственную ошибку, ради которой продукт затевался, — оценка,
   выданная за факт. До 1.9 у Claude процента нет вовсе, и это норма.
3. **Оценка отмечена.** Для каждого окна с `exact: false` в разметке есть `≈`
   и штриховка, для `exact: true` — ни того, ни другого.
   _Ловит:_ обратную ошибку — точное число Codex, показанное как оценка, и
   оценку Claude, показанную как точную.
4. **Отступы и типографика попапа — из блока попапа.** Существующий
   `tokens.test.ts` расширяется: у каждого нового компонента свой диапазон
   строк макета в `SPEC_LINES`, набор кеглей берётся из его же блока.
   _Ловит:_ подгонку попапа под числа раздела 0 — попап свёрстан на других
   значениях, и это не ошибка макета (см. подводные камни).
5. **В сеть за вёрсткой не ходим.** В собранном бандле рендерера нет ни одной
   ссылки на `http://` или `https://`.
   _Ловит:_ шрифты, уехавшие обратно на Google Fonts, — офлайн и приватность,
   заявленные в настройках, отваливаются молча и видны только без интернета.
6. **Числа одинаковы в CLI и в попапе.** На одном и том же значении и одной
   локали `formatTokens` даёт одну строку обоим.
   _Ловит:_ возврат второго форматтера с зашитой локалью — расхождение
   `344.9M` против `344,9M` на одной машине.

Проверка 4 обязана падать на подмене: временно поставить в компоненте попапа
`gap: 7` и `fontSize: 14` и убедиться, что тест краснеет. Проверку, которую не
видели красной, считать несуществующей.

Визуальную сверку делает человек; браузер со скриншотами не запускать.

## Подводные камни

1. **`tokens.test.ts` перебирает все `.tsx` в `components/`.** Новый компонент
   без своей строки в `SPEC_LINES` падает с «блок макета не найден» — это
   задумано, чтобы проверка не растворилась при росте папки. Правильная реакция —
   **добавить границы своего блока макета**, а не ослабить проверку до «всего
   раздела 0» и не выкинуть компонент из перебора.

2. **Попап свёрстан другими числами, чем раздел 0, и макет прав.** Строка
   агента в попапе: `gap:9px`, `padding:8px`; в разделе 0: `gap:10px`,
   `padding:8px 10px`. Полоса лимита в попапе `height:6px;border-radius:3px`, в
   разделе 0 — `8px`/`4px`. Кегли попапа — 9, 10, 12.5 — в шести ступенях
   раздела 0 отсутствуют.

   **Запрещено:** править макет, округлять `12.5` до `12`, приводить попап к
   числам раздела 0, «унифицировать» отступы. Раздел 0 — спецификация
   компонента в его собственном контексте, попап — другой контекст с более
   плотной сеткой, оба нарисованы осознанно.

   **Как делать:** размер полосы и плотность строки — необязательными
   параметрами компонента, значение по умолчанию равно значению раздела 0,
   чтобы существующая витрина и тест 2.4 остались нетронутыми. Набор
   допустимых кеглей в тесте берётся из блока конкретного компонента, ровно как
   уже сделано для отступов.

   На 2.4 это уже случилось: исполнитель нашёл расхождение макета с правилом
   отступов, честно описал его в отчёте — **и всё равно переверстал макет**,
   закрепив своё решение собственным тестом. Отчёта недостаточно. Если находишь
   расхождение с эталоном: оставить код по эталону, описать расхождение в
   отчёте, остановиться. `design/**` и `fixtures/**` не редактируются ни при
   каких обстоятельствах, включая «так очевидно правильнее».

3. **Строка агента в попапе богаче компонента 2.4.** Добавляются: бейдж `CL`/`CX`,
   ветка или ключ тикета после имени проекта, длительность, модель и точка входа
   справа, а цвет второй строки меняется с состоянием (`--tx2` работает,
   `--warn` ждёт). Это расширение `AgentRow` необязательными полями, а не второй
   компонент рядом: два похожих компонента разойдутся на первой же правке.
   Существующий рендер без новых полей обязан остаться прежним.

   **Что уже сделано в 2.2 и 2.3 и переделывать не надо:** у `AgentRow`
   четыре состояния (`thinking | waiting | idle | done`) и необязательный
   `rate`, который дописывается в ту же вторую строку («думает · 38k ·
   12.4k/мин»), а не третьей — высота строки списка в попапе 40. У `LimitBar`
   есть необязательная подпись `forecast`. Состояние `idle` («молчит») макетом
   не нарисовано: его точка контурная в `tx3`, а не в `warn`, потому что
   `warn` зовёт человека к машине, а `idle` значит «не вижу работы».
   Обоснования — в шапках компонентов и в `design-implementation.md`.

4. **`≈` в строке агента.** В макете попапа его нет, но у `LiveAgent` есть
   `approximate`: сессия с восстановленными запросами (1.3) показывается со
   знаком, как в CLI. Без него попап и `agentmeter live` покажут на одной
   машине разные числа, не сказав, какое точное, — тот же класс, что и долг
   форматтера в части 4.

5. **Длинные имена проектов.** В макете `pilot/flutter-pulse-mobile` обрезается,
   причём вторая строка обрезается с `direction:rtl` — видно хвост пути, а не
   начало. Тривиальный `text-overflow` даёт «pilot/flutter-pu…», то есть теряет
   ровно ту часть, по которой проект узнают.

6. **`node:sqlite` живёт только в main.** Любой импорт значения из
   `@agentmeter/core` в рендерере тянет его в браузерный бандл и роняет сборку
   или окно. В рендерер — только `import type`.

7. **Один экземпляр приложения.** Без `requestSingleInstanceLock()` второй
   запуск открывает вторую базу тем же файлом и второй вотчер на те же
   каталоги. Данные не портятся, но расход считается дважды на глазах у
   пользователя.

8. **Окно попапа — не обычное окно.** `frame: false`, `resizable: false`,
   `skipTaskbar: true`, скрытие по потере фокуса; на macOS `app.dock.hide()` и
   `LSUIElement`, иначе в доке висит иконка приложения без окон. Не показывать
   окно до `ready-to-show` — иначе при открытии видна белая вспышка на тёмной
   теме.

9. **Опрос не должен продолжаться при закрытом попапе в полную силу.** Живой
   слой дешёвый (2.1 держит снимок < 50 мс), но рендерер при скрытом окне не
   нужен вовсе: событие `live:update` шлётся только видимому окну.

10. **Пустых состояний в этом этапе нет.** «Пусто», «индексирование», «ошибка»,
    «никого нет» — это 2.8, раздел 7 макета. Здесь достаточно не падать на
    пустом снимке; рисовать эти экраны заранее, по своему представлению, не
    надо — они нарисованы, и не так.

11. **Собранный main не должен зависеть от `--experimental-strip-types`.**
    Пробы и CLI запускаются нодой прямо с исходников, приложение — нет: в
    Electron этот флаг не передашь. Main грузится из `dist/`, собранного `tsc`,
    и это надо проверить смоуком на собранной, а не на исходной версии.
