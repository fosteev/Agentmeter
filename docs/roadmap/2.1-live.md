# 2.1 — Живой слой: кто работает прямо сейчас

**Кто:** сам · **Объём:** M · **Блокирует:** 2.2 (состояния), 2.3 (темп),
2.5 (попап), 2.6 (контекстное окно), 2.7 (иконка трея)

До сих пор всё в проекте считалось постфактум: логи на диске, индекс, агрегаты,
таблица в терминале. Живой слой — первое место, где приложение отвечает на
вопрос «что происходит **сейчас**», и от этого меняются два правила сразу.

Первое: **чтение стало периодическим.** Трей опрашивает состояние раз в
секунду-две, и любой «пересчитаем на всякий случай при чтении» превращается в
полный проход по таблице запросов каждую секунду. Ровно это сейчас и делает
`limitsReport` — известный долг 1.10, и закрывается он здесь, потому что здесь
впервые появляется тот, кто вправе решать, когда пересчитывать.

Второе: **приложение впервые видит рождение и смерть процесса.** В логах этого
нет — и именно поэтому 1.3 закрыт «измеренной поправкой»: остаток ≤ 3.3% это
хвостовые прогревы после последнего ответа, их число зависит от того, сколько
процесс прожил после него, а лог такого не пишет. Живой слой это видит. Значит,
он обязан это записывать — с первого дня, потому что задним числом такой замер
не восстанавливается ниоткуда.

Если сделать этап плохо, ломается не «трей подтормаживает». Ломается вот что:
агент, у которого незнакомое значение `entrypoint`, просто не появляется в
списке (сегодня таких 8 из 9 на диске); мёртвая сессия висит вечно, потому что
pid переиспользовали; и замер времени жизни молча пишет нули, после чего 1.3
закрывается второй раз — уже неправдой.

## Часть 1. Кто жив

### Claude — реестр процессов есть

`~/.claude/sessions/<pid>.json`, по файлу на процесс. Формат на живой машине
(9 файлов, три версии CLI):

```json
{
  "pid": 41764,
  "sessionId": "ac111c6b-01a6-44b5-a170-42ec139b9ba3",
  "cwd": "/Users/fost/Projects/Agentmeter",
  "startedAt": 1786345908326,
  "procStart": "Mon Aug 10 07:11:48 2026",
  "version": "2.1.226",
  "kind": "interactive",
  "entrypoint": "claude-vscode",
  "messagingSocketPath": "/tmp/cc-socks/41764.sock",
  "name": "agentmeter-af",
  "nameSource": "derived"
}
```

Разбор уже написан — `packages/core/src/sources/claude/live.ts`,
`listLiveSessions()`. Он читает каталог, проверяет `process.kill(pid, 0)` и
отдаёт `LiveSession`. Здесь он чинится и обрастает связью с транскриптом.

### Codex — реестра нет вовсе

В `~/.codex` нет ничего похожего на `sessions/*.json`: проверено по всему
каталогу, включая `process_manager/chat_processes.json` (файл от июля, к CLI
отношения не имеет), `ipc/ipc.sock` и `session_index.jsonl` (там `thread_name` и
`updated_at`, но ни pid, ни признака жизни). Значит, у Codex живость выводится
**только из свежести роллаута**: `rollout-*.jsonl`, чей `mtime` моложе порога.

Это асимметрия, а не недоделка, и она обязана быть видна наружу: у Claude
`pid` есть и «процесс умер» — факт, у Codex `pid` нет и «замолчал» — догадка.
Критерий этапа «убитый процесс исчезает < 5 с» относится к Claude; для Codex
честная формулировка — «исчезает через порог тишины», и порог лежит в конфиге,
а не в коде.

## Часть 2. Что он потратил

Живой слой **не парсит логи сам**. Всё, что уже прочитано, лежит в индексе, и
его держит свежим вотчер (1.5, дебаунс 300 мс). Снимок собирается так:

- список живых — из `sessions/*.json` и свежих роллаутов (дёшево: 9 мелких
  файлов и `statSync`);
- расход и число запросов — из индекса, по `sessionId`;
- момент последней активности — `mtime` транскрипта;
- хвост лога читается **только если `mtime` сдвинулся с прошлого опроса** — не
  более 64 КБ с конца, до последней целой строки. Из хвоста берётся тип
  последней записи; на нём 2.2 построит состояния. В 2.1 он даёт одно:
  отличить «пишет прямо сейчас» от «файл не трогали три минуты».

Новая сессия появляется в `sessions/*.json` раньше, чем в её транскрипте
окажется первый запрос. Это нормально и это и есть «видна < 2 с»: агент
показывается с нулём токенов, цифры подъезжают следующим опросом. Прятать его
до первого запроса нельзя — тогда критерий не выполняется никогда.

## Часть 3. Замер времени жизни — долг 1.3

Ради чего всё: для каждой наблюдённой сессии пишется, **сколько процесс прожил
после своего последнего записанного запроса**. Это единственная величина,
которой не хватает, чтобы объяснить остаток ≤ 3.3% в `verify`.

Одна запись на сессию:

```ts
interface SessionLifetime {
  sessionId: string
  provider: Provider
  pid: number | null          // null у Codex — реестра нет
  startedAt: number           // из файла сессии
  firstSeenAt: number         // когда её впервые увидел живой слой
  lastSeenAt: number          // последний опрос, где процесс ещё жив
  endedAt: number | null      // первый опрос, где его уже нет
  lastRequestTs: number | null // последний запрос в индексе на момент смерти
  cliVersion?: string
}
```

Искомое — `endedAt − lastRequestTs`. Корреляция с недобором `verify` считается
позже и не входит в этап: сейчас задача одна — начать копить, потому что
восстановить это задним числом нельзя.

**Где это лежит — решение, а не деталь.** Не в индексе. Индекс полностью
производен от логов, на этом держится дешёвая миграция «снести и перечитать»
(правило 3 в `schema.ts`), и она уже применялась — версия 4. Положить туда
единственные невосстановимые данные значит поставить их в зависимость от ветки
кода, которая, как выяснилось в 1.10, до этого не выполнялась ни разу и падала.
Поэтому замер живёт отдельным файлом рядом с конфигом: `configDir()/lifetimes.jsonl`,
append-only, одна запись на строку, последняя запись про `sessionId` побеждает.
Формат выбран не из лени: это журнал наблюдений, его надо уметь показать как
доказательство при закрытии 1.3, а не только скормить коду.

## Часть 4. Лимиты перестают пересобираться на чтении — долг 1.10

Сейчас `limitsReport` зовёт `rebuildLimitWindows`: скрытая запись из читающего
модуля и полный проход по `requests` на каждый опрос. Правка:

1. `limitsReport` только читает (`readLimitWindows`).
2. Пересборка остаётся там, где меняются данные, — в конце `ingestAll`
   (уже так) и по явному вызову из живого слоя.
3. Живой слой пересобирает окна, когда изменился **вход** сборки: прошёл
   ingest либо поменялись `config.limits.claude`. Отпечаток последней сборки
   (JSON от `ClaudeLimits`) кладётся в `meta`, и несовпадение — единственный
   повод пересобрать без ingest.

Пункт 3 не украшение. Без него `agentmeter limits --no-ingest` после правки
потолка плана покажет старые `null`-проценты, и выглядеть это будет как «план
не задан» — то есть как честное незнание вместо устаревшего ответа.

Истечение окна пересборки **не требует**: окна фиксированные, отбор идёт по
`startsAt <= at < resetsAt` на чтении.

## Часть 5. Сутки на переводе часов — долг 1.10

`dayRange` держит сутки ровно 24 часа от локального `dayStartsAtHour`. Дважды в
год соседние дни перекрываются на час или расходятся на час: запросы этого часа
попадают в оба дня или ни в один. Граница дня считается календарно — от начала
дня до начала следующего, длина берётся какая получится.

## Контракт

- `LiveSession`, `Entrypoint`, `Provider` — `packages/core/src/sources/types.ts`,
  контракт 0.2, менять нельзя.
- Форма того, что уезжает в интерфейс, задана в `packages/ipc/src/index.ts`
  (контракт 0.4): `LiveAgent` с полями `state`, `tokens`, `rate`, `contextFill`.
  Живой слой обязан отдавать данные, из которых `LiveAgent` собирается без
  арифметики в рендерере. `rate` — этап 2.3, `contextFill` — 2.6; здесь они
  остаются `undefined`, но поля не переименовываются.
- `LiveAgent.state` в 2.1 заполняется одним грубым правилом: активность в
  пределах порога тишины → `working`, иначе `idle`; `waiting` и `done` — этап
  2.2. Правило заменяется целиком, поле — нет.
- Конфиг: пороги (тишина Claude, тишина Codex, период опроса) добавляются в
  `Config` секцией `live`, дефолты — в `DEFAULT_CONFIG`. Формат конфига —
  контракт 0.5, поэтому только добавление, без переименований.

## Критерий готовности

```bash
npm run check
node --experimental-strip-types scripts/probe/live-probe.ts
```

Проба даёт восемь проверок на живых логах. Каждая названа по поломке, которую
обязана поймать, а не по форме сравнения:

1. **Живые не теряются.** Каждый `sessions/*.json` с живым pid есть в снимке,
   каждый с мёртвым — отсутствует.
   _Ловит:_ разбор молча выбросил живую сессию (сегодня — по незнакомому
   `entrypoint`), агент работает, а в трее пусто.
2. **Точка входа распознана.** Ни у одной живой сессии `entrypoint` не
   `unknown`, если поле в файле непустое.
   _Ловит:_ возврат к белому списку из контракта, где `claude-vscode` и
   `claude-desktop` не значатся, — 8 сессий из 9 схлопываются в «неизвестно».
3. **Снимок ничего не пишет.** 20 снимков подряд не меняют ни размер файла
   индекса, ни число строк в `limit_windows`.
   _Ловит:_ пересборку окон из читающего пути — долг 1.10, ради которого этап
   вообще трогает `limitsReport`.
4. **Снимок дёшев.** Медиана 20 снимков подряд < 50 мс на живом индексе.
   _Ловит:_ возвращённый полный проход по `requests` в путь опроса трея —
   секундный опрос превращает его в постоянную нагрузку.
5. **Проценты не замерзают.** Индекс собран при `fiveHourCap: null`, затем
   читается с заданным потолком без нового ingest — процент обязан появиться.
   _Ловит:_ «убрали пересборку из чтения и забыли отпечаток входа», после чего
   устаревший `null` выглядит как честное «план не задан».
6. **Время жизни не обнуляется.** Между двумя снимками `firstSeenAt` сессии не
   меняется, `lastSeenAt` растёт, у исчезнувшей появляется `endedAt`.
   _Ловит:_ перезапись `firstSeenAt` на каждом опросе — тогда время жизни всегда
   ≈ 0, замер даёт ноль, и 1.3 закрывается второй раз неправдой.
7. **Замер переживает пересборку.** `agentmeter index --rebuild` не трогает
   `lifetimes.jsonl`.
   _Ловит:_ потерю единственных данных, которые не восстанавливаются ниоткуда.
8. **Сутки стыкуются.** В зоне с переводом часов (`TZ=Europe/Berlin`, обе даты
   перевода) конец дня N равен началу дня N+1, и ни один час не принадлежит
   двум дням.
   _Ловит:_ «ровно 24 часа» — дважды в год расход часа удваивается или
   пропадает.

Проверки 1, 2, 6 требуют живых процессов на машине; при их отсутствии проба
обязана **завершиться ненулевым кодом с текстом «нет живых сессий»**, а не
зелёным прочерком. Проверка, которая молчит на пустых данных, — это проверка,
которой нет.

Заодно в CLI появляется `agentmeter live [--json]` — тот же снимок в терминале.
Он и есть стенд: попап (2.5) показывает ровно эти поля, и расхождение видно
до того, как будет нарисован первый пиксель.

## Подводные камни

1. **`entrypoint` на диске не тот, что в контракте.** В файлах лежат
   `claude-vscode`, `claude-desktop`, `cli`; белый список в `live.ts` знает
   `cli | vscode | jetbrains | desktop | sdk | exec | unknown`. Сегодня это 8
   сессий из 9 в `unknown`. Нужна нормализация префикса `claude-`, и **новые
   значения не должны ронять сессию** — незнакомая точка входа это `unknown`
   плюс строка в `doctor`, а не пропуск агента. Тот же класс ошибки, что
   дрейф формата в 1.4.

2. **`procStart` записан в UTC, а `ps` печатает локальное время.** В файле
   `Mon Aug 10 07:11:48 2026`, у процесса — `Mon Aug 10 10:11:48 2026`, разница
   ровно смещение зоны (здесь +3). Наивное сравнение строк отвергнет **все**
   живые сессии, и список окажется пуст на машине, где всё работает.

3. **pid переиспользуется.** Файл остаётся после падения процесса, а система
   рано или поздно выдаёт тот же pid другому. Тогда `kill(pid, 0)` говорит
   «жив» про чужой процесс, и в трее висит вечный агент. Защита — сверка
   времени старта: `startedAt` в файле и `procStart` описывают один и тот же
   момент с точностью до секунды (проверено на 8 файлах из 9), и процесс,
   стартовавший заметно позже, — не наш. Кросс-платформенного способа взять
   время старта процесса из Node нет: Linux — `/proc/<pid>/stat`, macOS — один
   `ps -o lstart= -p …` **на все подозрительные pid сразу**, не по вызову на
   каждый. Windows — отдельный разговор, до 5.x там ничего не проверяется, и
   это записывается как известное ограничение, а не замалчивается.

4. **`kill(pid, 0)` бросает `EPERM` на чужой процесс.** Текущий `try/catch`
   считает мёртвым всё, что бросило, — для чужого процесса это правильный
   ответ по сути, но по случайности. Различать явно: `ESRCH` — мёртв,
   `EPERM` — жив, но не наш, тоже не показываем.

5. **Файл сессии пишется один раз при старте.** На всех девяти `mtime` совпал
   с `startedAt` до секунды. Значит, `mtime` файла сессии — **не** признак
   активности; активность только из транскрипта. Соблазн взять то, что под
   рукой, здесь даёт «все агенты думают всегда».

6. **Сокет `/tmp/cc-socks/<pid>.sock` есть не у всех.** Четыре файла из девяти
   (только 2.1.226). Как признак жизни не годится — версии 2.1.222 его не
   создают вовсе, и половина агентов исчезнет.

7. **Хвост лога — не парсер.** Читать не более 64 КБ с конца и только при
   сдвинувшемся `mtime`. Без второго условия десять живых сессий при опросе
   раз в секунду дают постоянные 640 КБ/с чтения ни за чем.

8. **Сабагенты — не отдельные агенты в трее.** Их транскрипты лежат в индексе
   отдельными сессиями (так и надо, 1.3), но своего процесса у них нет, и в
   списке «сейчас работают» они обязаны быть свёрнуты в родителя. Иначе один
   работающий агент показывается пятью, и число в шапке попапа врёт.

9. **Индекс отстаёт от реальности на дебаунс.** Расход живой сессии — это
   расход на момент последнего ingest, то есть до 300 мс назад плюс время
   разбора. Для показа этого достаточно, но складывать его с чем-то, что
   прочитано мимо индекса, нельзя — получится двойной счёт того же запроса.

10. **Замер времени жизни портится «улучшением».** Соблазн номер один — писать
    `endedAt` при выходе приложения для всех, кого видим сейчас. Так нельзя:
    смерть агентметра не есть смерть агента, и такая запись подменит замер
    выдумкой. Сессия, которую перестали видеть без наблюдения смерти (закрыли
    приложение, ушли в сон), обязана остаться с `endedAt: null` — «не знаем»
    здесь дороже правдоподобного числа.
