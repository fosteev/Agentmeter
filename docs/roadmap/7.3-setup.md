# 7.3 — Окно первичной настройки

**Кто:** сам · **Объём:** L · **Блокирует:** ничего

Сегодня первый запуск выглядит так: приложение встаёт в трей и молча читает
логи. Человек не знает ни что нашлось, ни куда это уходит, ни сколько ждать.
Мастер (макет, раздел 11, строки 1807–2073) показывает найденное, спрашивает
план и пороги и говорит, сколько займёт индексирование. Сделать плохо здесь
значит завести второй набор настроек: экран, который спрашивает то, чего потом
нигде не изменить.

## Файлы

```
создать:    apps/desktop/src/renderer/components/Setup*.tsx  (шаги мастера)
            apps/desktop/src/renderer/setup.html, setup-main.tsx
править:    apps/desktop/src/main/index.ts      (окно мастера, показ при первом запуске)
            apps/desktop/src/main/config.ts     (флаг «мастер пройден»)
            apps/desktop/test/tokens.test.ts    (SPEC_LINES на раздел 11)
            docs/roadmap/design-implementation.md
не трогать: apps/desktop/src/renderer/components/Settings*.tsx — мастер их не дублирует,
            а показывает те же значения
```

## Контракт

Все значения мастера читаются и пишутся тем же конфигом, что и «Настройки» —
[`apps/desktop/src/main/config.ts`](../../apps/desktop/src/main/config.ts).
Ни одной настройки, которой нет в разделе 6 макета (строки 1168–1249).

Список моделей на первом шаге приходит из разобранных логов, а не зашит: чипы
рисуются по тому, что встретилось. Провайдер, у которого логи не нашлись,
выключен и предлагает указать путь вручную — теми же полями, что «Пути к логам»
в настройках.

## Критерий готовности

```bash
npm test -w @agentmeter/desktop -- setup
npm run check
```

Плюс на собранном приложении: «Пропустить настройку» даёт тот же конфиг, что
«Начать» с нетронутыми значениями.

## Данные

Макет: раздел 11, строки 1807–2073 — три шага. Разделы «Настройки» (1168–1249) и
«Состояния попапа» (1250–1309): после «Начать» окно уходит в трей и показывает
«первичное индексирование».

**Светлой темы у раздела 11 в макете нет.** Верстается по токенам, как 3б и 8б:
своих чисел светлая версия не приносит, только пары `--bg`/`--lbg`.

## Подводные камни

- **«Пропустить» обязано давать дефолты конфига**, а не собственный набор:
  иначе у продукта два разных первых запуска, и воспроизводится жалоба только у
  одного из них.
- **Оценка времени индексирования — оценка.** «≈3 с» и «≈2 мин» на третьем шаге
  считаются от объёма найденных логов и помечаются знаком `≈`, как всё
  посчитанное, а не измеренное.
- **Мастер не блокирует трей.** Пока человек читает три шага, индекс уже
  собирается: закрытое окно мастера не должно означать потерянные полчаса.
- **Второй раз мастер не показывается**, но открывается из настроек — иначе
  единственный способ его перечитать это стереть конфиг.
