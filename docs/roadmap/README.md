# Брифы этапов и модели

Здесь два разных вида документов, и путать их нельзя.

**Бриф** — описание этапа, который вот-вот пойдёт в работу. Самодостаточен: его
можно отдать исполнителю целиком, без чтения остальной документации. Живёт от
написания до закрытия этапа.

**Модель** — как устроен расчёт и почему именно так, с эталоном и разведкой.
Переживает этап: код показывает, что считается, а модель — почему это правильно.

## Правила, чтобы это не сгнило

1. **Статусы живут только в [`../roadmap.md`](../roadmap.md).** Здесь их нет.
   Два места со статусами разъедутся на второй неделе — проверено человечеством.
2. **Бриф пишется на веху вперёд, не дальше.** Этапы, до которых ещё две вехи,
   перепишутся после того, как ближайшая покажет, где я ошибся в модели данных.
   Писать их сейчас — сочинять фантазии с видом занятости.
3. **Нет брифа — нет делегирования.** Если задачу нельзя описать по шаблону,
   значит она недостаточно понята, чтобы её отдавать.
4. **Бриф удаляется вместе с закрытием этапа.** Что осталось от работы — код,
   тесты и эталоны, а не описание намерений. В git история сохранится.
5. **Контракты сюда не копируются.** Типы, схемы и сигнатуры живут в одном
   экземпляре — в коде; ссылаться на файл, а не пересказывать. Копия отстаёт
   молча и потом уверенно врёт: к M3 копия модели 0.2 в роадмапе разошлась с
   `sources/types.ts` на девять полей, а бриф 1.5 описывал схему индекса второй
   версии при живой четвёртой. Оба удалены.

## Шаблон

См. [`_template.md`](_template.md). Четыре обязательных раздела — файлы,
контракт, критерий, данные. Без любого из них исполнитель сочинит недостающее
сам и отрапортует об успехе.
