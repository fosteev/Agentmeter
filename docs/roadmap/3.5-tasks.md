# 3.5 — Задача: дерево сессий, а не файл

Модель того, из чего складывается одна строка ленты, и **измерение**, закрывающее
открытый вопрос роадмапа «Одна сессия = одна задача?».

Здесь две разные вещи под одной вывеской. Сабагенты — задача из нескольких
сессий, связанных **записанной** ссылкой. Resume и `--continue` — предполагаемая
задача из нескольких файлов, связанных догадкой. Первое сделано, второго нет — и
это результат измерения, а не нехватка времени.

## Что померено

Прогон по всему, что лежит на диске: 268 транскриптов Claude, 348 роллаутов
Codex, 616 сессий в индексе. Воспроизвести —
`node --experimental-strip-types scripts/probe/resume-scan.ts`.

### Resume и `--continue` пишутся в тот же файл

| наблюдение                                              | Claude       | Codex        |
| ------------------------------------------------------- | ------------ | ------------ |
| сессий с внутренним разрывом больше часа                | 42 из 268    | 29 из 348    |
| самый длинный разрыв **внутри одной сессии**            | 93.2 ч       | 75.4 ч       |
| файлов, делящих хоть один идентификатор записи с другим | 0 из 259     | —            |
| первых записей со ссылкой на запись в другом файле      | 0 из 259     | —            |
| ссылок на предыдущую сессию в `session_meta`            | —            | 0 из 348     |

Разрыв в 93 часа внутри одного файла ничем, кроме продолжения старой сессии,
быть не может: значит `--resume` дописывает в тот же транскрипт, сохраняя
идентификатор. Ни одной пары файлов, которые следовало бы склеить, в корпусе
нет — ни по общему `uuid` записи, ни по `parentUuid` первой записи, ни по полю
`session_meta` у Codex (там 18 форм заголовка, и ни в одной нет ссылки на
предшественника; поле `session_id`, встречающееся у 42 роллаутов, всегда равно
собственному `id`).

**Значит признака для склейки не существует, а не «мы его не нашли».** Склеивать
нечего: одна сессия — одна задача.

### Почему нельзя склеить «на всякий случай» по соседству

Соблазн собрать цепочку по общему каталогу и стыку по времени проверяется
счётом:

| правило склейки                              | склеило бы пар |
| --------------------------------------------- | -------------- |
| тот же каталог и провайдер, стык ≤ 1 мин     | 45             |
| тот же каталог и провайдер, стык ≤ 5 мин     | 113            |
| тот же каталог и провайдер, стык ≤ 30 мин    | 202            |

113 склеек при **нуле** записанных связей — это 113 задач, исчезнувших из ленты
внутрь чужих строк без единого подтверждения. Ветка соседей при этом совпадает
почти всегда (109 против 4), то есть и она ничего не различает.

Довод «ну сессии же идут подряд» тоже не работает: пар сессий в одном каталоге
11 429, из них внахлёст всего 64. Последовательность — обычное состояние работы
в одном проекте, а не признак продолжения.

Хуже того, у соседства есть измеренный контрпример. Пары роллаутов Codex,
запущенных с **тем же первым промптом** через минуту друг за другом, в корпусе
есть: `019f501e` в 10:39:37 и `019f501f` в 10:40:54, оба в
`flutter-pulse-mobile`, первый оборвался на четвёртом ответе, второй прошёл
задачу целиком. Это не продолжение, а **повторный запуск той же работы** —
и склейка спрятала бы именно тот факт, ради которого счётчик и написан: работа
оплачена дважды.

### Сабагенты — единственная настоящая связь

| наблюдение                              | значение                       |
| ----------------------------------------- | ------------------------------ |
| сессий с записанным родителем           | 9 из 616                       |
| задач с детьми                          | 3                              |
| детей на задачу                         | 3, 4, 2                        |
| расход детей                            | 1.56M, 1.54M, 1.28M            |
| дети в другом дне, чем родитель         | 0 из 9                         |
| `agent_type` заполнен                   | 9 из 9 (`Explore`, `Plan`)     |
| `title` у ребёнка                       | нет ни у одного                |

Корпус тонкий: транскрипты сабагентов приложение чистит вместе с остальным
хламом в `~/.claude` (на диске 184 файла в `subagents/`, из них расшифровок —
девять, остальное `*.meta.json` и 139 огрызков воркфлоу). Поэтому поведение
проверяется посевом индекса руками, а не фикстурой из живых логов, — как в
`apps/desktop/test/task.test.ts`.

## Модель

**Задача — корень и все его потомки.** Свёрнутая строка показывает расход
дерева: у задачи с сабагентами в шапке 276 запросов, и все они её. Это уже так
с 3.4 (`taskSessions`/`findRoot`), 3.5 добавляет к строке **список** детей.

**Список детей плоский, а не дерево.** Сабагент может породить сабагента, и
вложенный список показал бы один и тот же расход на двух уровнях — сумма детей
перестала бы сходиться с разницей «дерево минус корень». Плоский список
отвечает на единственный вопрос, который к нему есть: из чего сложился расход.

**У ребёнка своя строка, но не своя карточка.** Карточка родителя уже собрана по
всему дереву — таймлайн, инструменты и файлы включают запросы детей (3.4).
Вторая карточка на ту же работу показала бы те же столбики подмножеством, и
разойтись им не с чем, кроме как в голове у смотрящего.

**`foldSubagents: false` разворачивает детей в самостоятельные строки**, и тогда
расход родителя их не включает. Иначе одна и та же тысяча токенов оказалась бы и
в строке ребёнка, и в строке родителя, а итог дня остался бы прежним — то есть
сумма строк перестала бы сходиться с шапкой. Это и проверяется:
`Σ tasks == Σ today` обязано держаться **в обоих** режимах.

## Что осталось нечестного, и это названо

**Сабагент Codex опознаётся, но не привязывается.** Один роллаут из 348
(`019dd82d`, 29 апреля) написан с `source: {"subagent": "review"}` — то есть
Codex умеет сабагентов и помечает их. Родителя в заголовке нет: ни ссылки, ни
идентификатора вызова. Привязать такую сессию можно было бы только по каталогу и
времени, то есть тем самым правилом, которое выше отвергнуто счётом. Поэтому
сабагент Codex сейчас стоит в ленте отдельной задачей. Дыра измерена: 1 из 348.

**Ключ, по которому это придётся переделать.** Если провайдер начнёт писать
ссылку на предыдущую сессию — у Claude полем в первой записи, у Codex ключом в
`session_meta`, — склейка станет возможной на измеренном признаке. Проба
`resume-scan.ts` следит именно за этим: незнакомый ключ заголовка Codex и
`parentUuid` первой записи, ведущий в другой файл, делают её красной.
