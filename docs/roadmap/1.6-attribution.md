# 1.6 — Атрибуция: маржинальная дельта, компакт, дележ

**Кто:** модель и эталон — сам, реализация — Codex · **Объём:** L
**Блокирует:** 1.7, 1.10, весь M4 · **Ждёт:** 1.1, 1.2, 1.3, 1.5 — все готовы

Колонка `tool_calls.marginal_tokens` в схеме есть с 0.3 и до сих пор всегда
равна нулю. Этот этап её заполняет — то есть отвечает на вопрос, ради которого
продукт затевался: **сколько на самом деле стоил каждый вызов инструмента**.

Ошибка здесь тихая по построению. Размер результата в логе выглядит как
готовый ответ, он всегда есть, он правдоподобен — и он врёт: на живых данных
разброс «байт на токен» от 2 до 200 в зависимости от того, картинка это или
текст, и обрезал ли CLI вывод по дороге в промпт. Реализация, сверенная сама с
собой, сойдётся при любой формуле и покажет пользователю уверенную неправду.
Поэтому эталон посчитан руками до кода и лежит в `fixtures/attribution/`.

## Формула

```
маржинальная стоимость запроса N = ctx(N+1) − ctx(N) − output(N)
```

`ctx` — `Request.contextTokens`, весь промпт запроса. У Claude это
`input + cacheRead + cacheWrite`, у Codex — `input_tokens` (кэшированная часть
в нём уже сидит). Разность промптов двух соседей — ровно то, что между ними
добавилось: ответ ассистента плюс результаты его вызовов. Ответ известен,
остаток — цена тулов. Формула одна на обоих провайдеров, отдельной ветки «если
claude» в ней быть не должно.

`N+1` — **следующий запрос с `origin === 'log'`**.

Прототип на python (`scripts/probe/marginal-attribution.py`) считает то же самое
в форме `cache_creation(N+1) − output(N)`. Брать его как образец формулы, но не
как реализацию: он не знает про реконструированные запросы, работает по одному
проекту и на Codex не переносится вовсе.

### Проверка формулы независимым источником

Codex пишет в тексте результата команды строку `Original token count: N` — свой
счёт токенов вывода. На **435 одиночных вызовах** с выводом крупнее 2000 токенов
медиана отношения «наша дельта / его счёт» равна **1.00** (p10 = 0.57 —
обрезанные выводы, p90 = 1.42). На мелких выводах отношение 1.23: постоянная
обвязка вызова в полтора-два десятка токенов. Это единственное место, где модель
сверяется не с собственной арифметикой, — поэтому оно вынесено в пробу.

## Что делаем по шагам

Порядок важен: пункт 1 меняет цифры, на которые опирается всё остальное.

### 1. Сначала — починить пары «вызов → результат» у Codex (находка разведки)

`token_count` в роллауте пишется **между** `function_call` и
`function_call_output`. `consumeTokenCount` в этот момент делает
`pendingTools.clear()`, и результат, пришедший следом, заводит **новую** запись
с тем же `call_id`. Итог на живых данных: каждый вызов попадает в модель дважды —
именованным с `resultBytes = 0` на своём запросе и безымянным (`name:
'unknown'`, `kind: 'unknown'`) с байтами на следующем.

```
seq 0  tools exec_command:0
seq 1  tools unknown:2700 | exec_command:0 | exec_command:0
seq 2  tools unknown:5400 | unknown:1350 | exec_command:0 …
```

Суммы токенов это не ломает, поэтому `codex-live.ts` (он сверяет только usage с
накопительным итогом) молчал. Ломает оно ровно то, что делает 1.6: список тулов
запроса и вес каждого при дележе.

Чинить: результат обязан находить свой вызов **и после того, как запрос уже
собран**. Держать в состоянии карту `call_id → ToolCall` по всем уже выпущенным
запросам и дописывать `resultBytes` в неё. Запись без своего `function_call`
(файл начался посреди хода) заводится как сейчас — `unknown`, это документировано.

Проверка: в пределах сессии каждый `call_id` встречается **ровно один раз**.
Сейчас — вдвое чаще.

Заодно: `view_image` возвращает картинку, а `hasImage` у Codex не выставляется
никогда. Ставить `hasImage = true` результату вызова `view_image` — иначе он
пойдёт в дележ с весом пустой строки.

### 2. Атрибуция

Новый модуль `packages/core/src/attribution/marginal.ts`. Чистая функция над
`Request[]`, ничего не знает про файлы и базу:

```ts
export interface MarginalOptions {
  /** Байт результата на токен промпта. Claude 2.7, Codex 3.7. */
  bytesPerToken?: number
  /** Вес картинки в дележе, в токенах. По умолчанию 400. */
  imageTokens?: number
}

export interface MarginalStats {
  measured: number // вызовов с измеренной дельтой
  split: number // вызовов, получивших долю дельты
  unknown: number // вызовов, для которых дельта неизмерима
  attributed: number // сумма marginalTokens
}

/** Проставляет `marginalTokens` и `marginalBasis` на месте. */
export function attributeMarginal(
  requests: Request[],
  provider: Provider,
  options?: MarginalOptions,
): MarginalStats
```

Вызывается последним шагом в `parseSessionFile` и `parseRolloutFile` — чтобы
разобранный файл всегда был атрибутирован, и не существовало пути, на котором
`marginalTokens` молча остаётся нулём. `ingest`/`store` от этого не меняются,
кроме записи двух новых колонок.

### 3. Правила

**Атрибутируется только запрос, у которого есть хотя бы один `tool_use`.**
Остаток на запросе без тулов — это ход пользователя, к инструментам он
отношения не имеет.

**Дельта считается, если выполнено всё:**

1. есть следующий запрос с `origin === 'log'`;
2. у него `compacted === false`;
3. у текущего запроса `interjectedBytes === 0`.

Иначе все вызовы этого запроса получают `marginalTokens = 0` и
`marginalBasis = 'unknown'`.

**Отрицательный остаток** обрезается по нулю, но остаётся `measured`: это шум
учёта кэша (на живых данных 64 случая из 16 380, худший −333), а не сломанная
цепочка.

**Один вызов в запросе** получает весь остаток: `marginalBasis = 'measured'`.
Никаких констант, чистое измерение.

**Несколько вызовов** делят остаток пропорционально весам,
`marginalBasis = 'split'`:

```
вес = hasImage ? imageTokens : resultBytes / bytesPerToken
```

- все веса нулевые → делить поровну;
- целочисленное распределение — по наибольшему остатку: раздать целые части,
  недостающие токены отдать вызовам с наибольшей дробной частью, при равенстве —
  тому, кто в ответе стоял раньше. Правило обязано быть детерминированным:
  переиндексация не имеет права дать другие цифры;
- **сумма долей обязана совпасть с остатком до токена.**

Дележ — оценка, и метка `split` существует ровно для того, чтобы интерфейс мог
показать её штриховкой. Это не мелочь: на живых логах через дележ проходит
**26.9%** всей маржинальной суммы (12% запросов).

**Почему картинка весит константой.** У результата с картинкой в логе лежит
base64: медиана 83 КБ при реальной цене 427 токенов, то есть ≈200 байт на токен
против 2.7 у текста. По байтам такая картинка забрала бы у соседа по вызову всё.
У скриншотов бывает наоборот — base64 в лог не пишется вовсе, `resultBytes = 0`
при `hasImage = true`, и тогда по байтам картинка не получила бы ничего.
Константа 400 (медиана 33 измеренных одиночных вызовов, p10 = 64, p90 = 1669)
груба, но ошибается в разы, а не в сто раз.

**Чем заменяется дельта там, где её нет: ничем.** Соблазн подставить
`resultBytes / bytesPerToken` понятен и его надо погасить сразу. Оценка по
байтам на живых данных имеет p90 = 73 байта на токен при медиане 2.7 — то есть
на хвосте врёт в 27 раз, и в разбивку прилетит шестизначное число там, где
настоящая цена — пара тысяч. При дележе тот же вес безопасен, потому что сумма
долей закреплена измеренной дельтой и ошибка только перераспределяет её внутри
группы. Здесь закреплять нечем. Поэтому `unknown` — это ноль и явная метка, а не
выдуманное число. Цена вопроса невелика: компакт съедает **0.7%** маржинальной
суммы, хвостовых вызовов без преемника на всём диске — **7 штук**, перебивок —
0.61% запросов с тулами.

## Контракт: две новые вещи в модели

Оба поля добавлены осознанно и в одном месте — это правка M0, она уже принята.

`packages/core/src/sources/types.ts`:

```ts
/** Откуда взялась цифра в `marginalTokens`. */
export type MarginalBasis =
  | 'measured' // единственный вызов запроса, дельта целиком
  | 'split' // доля дельты, поделённой между параллельными вызовами
  | 'unknown' // дельта неизмерима: компакт, хвост сессии, перебивка

interface ToolCall {
  marginalBasis: MarginalBasis // рядом с marginalTokens
}

interface Request {
  /**
   * Байт текста, который пользователь дописал после этого запроса и до
   * следующего. Не ноль — значит, дельта кэша несёт не только результаты
   * тулов, и атрибутировать её нельзя.
   */
  interjectedBytes: number
}
```

`interjectedBytes` считают оба парсера:

- **Claude** — записи `type: 'user'`, в которых есть блоки `type: 'text'` (или
  `content` — строка), кроме блоков `tool_result`; длина в байтах приписывается
  последнему увиденному `requestId`. Текст, стоящий до первого `assistant`, —
  это открывающий промпт сессии, он относится к `cacheWrite` первого запроса и
  здесь не учитывается.
- **Codex** — `event_msg/user_message`, приписывается последнему выпущенному
  запросу. Только он: тот же текст лежит ещё и в `response_item/message`, и
  считать оба — считать дважды.

Схема (`packages/core/src/index/schema.ts`), `SCHEMA_VERSION = 3`, миграция
совместимая, без `rebuild`:

```sql
ALTER TABLE tool_calls ADD COLUMN marginal_basis TEXT NOT NULL DEFAULT 'unknown';
ALTER TABLE requests  ADD COLUMN interjected_bytes INTEGER NOT NULL DEFAULT 0;
```

`SCHEMA_SQL` для чистой базы правится в тех же двух местах. `store.ts` пишет обе
колонки.

Счётчики файлов в пробах плавают — Claude Code сам подчищает старые транскрипты.
Держаться надо не количеств, а нулей: ноль незнакомых типов, ноль падений,
полное схождение у Codex, 5 точных при 3.30% у `verify-live`. **Если
`verify-live` стал хуже — сломана модель, а не тест.**

`scripts/probe/attribution-live.ts` печатает каждую проверку отдельной строкой с
числом и падает на нарушении:

1. **Сохранение.** Для каждого атрибутированного запроса сумма `marginalTokens`
   его вызовов равна `max(0, ctx(N+1) − ctx(N) − output(N))` **до токена**.
   Нарушений — ноль, по обоим провайдерам, по всем файлам.
2. **Покрытие.** Доля вызовов и доля токенов по каждому `marginalBasis`, отдельно
   по провайдерам. `unknown` не больше **3%** вызовов с тулами; из них доля
   «перебивка» не больше 2%.
3. **Независимая сверка Codex.** Одиночные вызовы, в тексте результата которых
   есть `Original token count: N` при N > 2000: медиана `marginalTokens / N` в
   пределах **0.90–1.15**. Это единственная проверка не против самих себя.
4. **Пары вызов→результат у Codex.** В пределах сессии каждый `call_id`
   встречается один раз; вызовов с `name === 'unknown'` — не больше 1% (сейчас
   их половина всех).
5. **Калибровка.** Медиана «байт на токен» на одиночных текстовых вызовах:
   печатать по провайдерам, падать при выходе за 2.0–3.5 (Claude) и 3.0–4.5
   (Codex). Уехало — значит, изменилась либо модель, либо формат.
6. **Цепочка не перемешана.** Ни один родительский транскрипт не содержит
   одновременно запросов с `isSidechain` и без (сейчас таких ноль). Если появятся,
   соседство считать внутри ветки, а не сквозь — но сначала это надо увидеть.
7. **Скорость.** Атрибуция всего диска добавляет к разбору не больше 10%.

Модульные тесты (`packages/core/test/attribution/marginal.test.ts`) — на обеих
цепочках эталона, повызовно: `marginalTokens` и `marginalBasis` каждого вызова
сверяются с `*.expected.json`, плюс итоги (`attributedTokens`, счётчики по
basis). Отдельно — вырожденные случаи: сессия из одного запроса, сессия без
запросов, запрос с десятью вызовами и нулевыми весами.

## Подводные камни

1. **Реконструированные запросы нельзя брать в соседи, но нельзя и выкидывать.**
   Их `cacheWrite` уже сидит внутри `cacheRead` следующего записанного запроса,
   поэтому формула через `ctx` ничего не теряет сама. А вот если посчитать
   дельту *до* реконструированного, тулы получат почти ноль: он несёт ответ
   ассистента и ни одного результата. В эталоне это запрос 5 цепочки Claude.

2. **Компакт рвёт соседство вперёд, а не назад.** У запроса, за которым идёт
   сжатый, дельта бессмысленна (в эталоне −13 101). У самого сжатого запроса
   дельта считается как обычно. `cacheWrite` сжатого запроса — цена пересборки
   префикса, отдельная статья расхода; на тулы её не размазывать.

3. **`compacted` — наша эвристика, а не флаг из лога** (`looksCompacted`: префикс
   был больше 10 000 и упал ниже 60%). Мелкие просадки префикса компактом не
   считаются и дают отрицательный остаток — он обрезается по нулю. Не пытаться
   ловить их отдельным правилом: живые данные показывают 0.4% таких случаев с
   медианой в пару десятков токенов.

4. **`resultBytes` у Claude и у Codex меряются по-разному** — `JSON.stringify(…)
   .length` против `Buffer.byteLength(строка)`. Это задокументированное «сколько
   лежит в логе», и в дележе оно работает, потому что группа всегда
   одного провайдера. Не «унифицировать» — это поменяет цифры в 1.2 и 1.5.

5. **Вызов `Agent` стоит не столько, сколько сабагент.** Его дельта — размер
   отчёта, который сабагент вернул в промпт родителя, обычно вшестеро меньше
   собственного расхода сабагента (тот живёт отдельной сессией со своим файлом).
   Обе цифры верны и обе нужны; складывать их — двойной счёт. Развязка — 3.5,
   здесь просто не мудрить: `Agent` атрибутируется как любой другой тул.

6. **`output` вычитается целиком, вместе с `reasoning`.** У Codex `reasoning`
   лежит отдельным полем, и соблазн вычесть `output − reasoning` (мол,
   рассуждение в промпт не возвращается) выглядит осмысленно. Независимая сверка
   говорит обратное: с полным `output` медиана отношения к `Original token
   count` равна 1.00, а без — систематически завышена.

7. **`STRICT`-таблицы не прощают типов.** `marginal_basis` — строка из трёх
   значений, `undefined` в биндинге `node:sqlite` это ошибка, а не `NULL`.

8. **Не изобретать оценку там, где написано `unknown`.** См. раздел про
   константы: на хвосте байтовая оценка врёт в 27 раз. Продукт измерительный —
   пустое место честнее выдуманного числа.
