# 1.2 — Парсер Codex

**Кто:** Codex · **Объём:** M · **Блокирует:** 1.5, 1.8 · **Ждёт:** 0.2, 0.6 — оба готовы

Превращает `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` в ту же
нормализованную модель, что и парсер Claude. Формат другой, модель общая —
в этом весь смысл.

## Файлы

```
создать:    packages/core/src/sources/codex/parse.ts
            packages/core/src/sources/codex/limits.ts
            packages/core/src/sources/codex/index.ts
            packages/core/test/codex/*.test.ts
не трогать: packages/core/src/sources/types.ts    ← контракт, задан
            packages/core/src/sources/claude/**   ← чужой этап
            fixtures/**, scripts/**               ← только читать
```

## Контракт

```ts
parseRolloutFile(path: string): ParseResult
parseRolloutChunk(path: string, fromOffset: number): { requests: Request[]; offset: number }
readLimits(path: string): LimitWindow[]
```

Типы — из `packages/core/src/sources/types.ts`, менять нельзя.

## Формат: где что лежит

Каждая строка — `{ timestamp, type, payload }`. Значимые `type`:
`session_meta`, `turn_context`, `event_msg`, `response_item`.

| что | где |
|---|---|
| сессия | `session_meta.payload`: `id`, `cwd`, `cli_version`, `originator`, `model_provider`, `git.branch` |
| ход | `event_msg/task_started` (`turn_id`, `model_context_window`), `task_complete` |
| **расход** | `event_msg/token_count`, поле `info` |
| лимиты | `event_msg/token_count`, поле `rate_limits` |
| вызов тула | `response_item/function_call`: `name`, `arguments`, `call_id` |
| результат тула | `response_item/function_call_output` по тому же `call_id` |
| MCP | `event_msg/mcp_tool_call_end`: `invocation.server`, `invocation.tool`, `duration`, `result` |
| текст задачи | `event_msg/user_message` |

## Главное правило: один `token_count` — один `Request`

`info` содержит две суммы, и путать их нельзя:

```
total_token_usage   накопительный итог сессии на этот момент
last_token_usage    расход одного последнего запроса   ← вот это и есть Request
```

Раскладка на нашу модель (проверено на фикстуре):

```
Request.input     = last.input_tokens - last.cached_input_tokens   свежий ввод
Request.cacheRead = last.cached_input_tokens                       cached_input входит в input_tokens
Request.output    = last.output_tokens                             reasoning уже внутри
Request.reasoning = last.reasoning_output_tokens
Request.cacheWrite = 0                                             Codex про запись кэша не сообщает
Request.contextWindow = task_started.model_context_window
```

`cached_input_tokens` — **подмножество** `input_tokens`, а не добавка к нему:
`total_tokens == input_tokens + output_tokens`. Сложить их — завысить ввод
вдвое на длинных сессиях.

Записи `token_count` с `info: null` встречаются (обновление одних лимитов без
расхода) — из них берутся только `rate_limits`, `Request` не создаётся.

## Лимиты — единственное место, где у нас есть точные цифры

`rate_limits.primary` — пятичасовое окно, `secondary` — недельное; у каждого
`used_percent`, `window_minutes`, `resets_at` (unix-секунды). Плюс `plan_type`
и `credits`. Всё это приходит от провайдера, поэтому `LimitWindow.exact = true`
— в отличие от Claude, где мы считаем сами и всегда помечаем оценкой.

## Критерий готовности

```bash
npm test -w packages/core -- codex
```

1. `fixtures/codex/rollout.jsonl` разбирается без исключений и совпадает с
   `rollout.expected.json` глубоким сравнением.
2. **Сумма `last_token_usage` по всем `token_count` равна последнему
   `total_token_usage`** — по каждому полю. Это встроенная в формат проверка на
   то, что ни один запрос не потерян и ни один не посчитан дважды; она должна
   быть отдельным тестом, а не комментарием.
3. `readLimits` возвращает окна с `exact: true` и разобранным `resets_at` в
   epoch ms.

## Подводные камни

1. **`resets_at` в секундах**, а вся модель в миллисекундах. Умножать.
2. **`originator`** — это `codex-tui`, `codex-exec` и подобное; отображать в
   `Entrypoint` (`cli` / `exec`), незнакомое — `unknown`, а не выдумывать.
3. **Роллаут может обрываться** на середине строки — как и у Claude. Чанковое
   чтение обязано вернуть оффсет начала неполной строки.
4. **`function_call.arguments` — строка с JSON**, а не объект. Её длина нужна,
   содержимое нет.
5. **Реконструкции незаписанных запросов здесь нет.** Это особенность Claude
   Code (см. 1.3), у Codex цепочка кэша так не читается. Не переносить.
