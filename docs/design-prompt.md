# Промпт для дизайна

Ниже — готовый к копированию бриф. Вставлять целиком.
Цифры в примерах настоящие, сняты с машины разработчика: макеты на них выглядят
правдоподобно, а заодно сразу видно, где вёрстка поедет от длинных чисел и
кириллических названий.

## ↓ КОПИРОВАТЬ ОТСЮДА ↓

Спроектируй интерфейс десктопного приложения **Agentmeter**.

### Что это

Локальный счётчик расхода токенов для кодинг-агентов (Claude Code и OpenAI Codex).
Живёт в системном трее, читает логи агентов с диска и отвечает на четыре вопроса:

1. Кто из агентов работает прямо сейчас и над чем.
2. Сколько осталось до упора в лимит.
3. Какие сегодня были задачи и сколько токенов сожрала каждая.
4. **Куда именно утекли токены** — какой инструмент, MCP-сервер, скилл, сабагент
   или скриншот их съел.

Аудитория — один человек, разработчик, который гоняет несколько агентов
параллельно по разным проектам. Это личный измерительный прибор, а не корпоративный
дашборд: смотрят в него по десять секунд, между делом, много раз в день.

### Платформы

Electron, одна вёрстка на macOS, Windows и Linux. Учти оба поведения трея:
на macOS это попап под иконкой в menu bar, на Windows — окно у иконки в трее.
Светлая и тёмная темы обязательны, тёмная — основная (у агентов терминальная
аудитория). Плотность информации высокая, но без визуального шума.

### Экраны

**1. Иконка в трее.** Нарисуй набор состояний: простой; один агент работает;
несколько агентов работают; лимит на исходе; лимит выбран. Место крошечное —
покажи, как в него влезает и число активных агентов, и уровень тревоги. Учти
монохромные требования macOS menu bar.

**2. Попап из трея, ~400×600.** Главный экран, его видят чаще всего.
Сверху — активные агенты. Под ними — лимиты. Внизу — итог за сегодня и вход
в большое окно. Пример содержимого:

```
Сейчас работают
  Claude · ollama-bar · main · Opus 5 · VS Code
      идёт 4 мин · 38k токенов · думает
  Claude · pilot/flutter-pulse-mobile · GARM-810 · Opus 5 · терминал
      идёт 12 мин · 214k токенов · ждёт ответа
  Codex · troy · exec
      идёт 1 мин · 12k токенов · думает

Лимиты
  Codex, недельное окно      5%    сброс через 6 д 4 ч        [точно]
  Claude, 5-часовое окно    68%    сброс в 18:40              [оценка]
  Claude, недельное         31%    сброс в пн                 [оценка]

Сегодня
  22 сессии · 344.9M токенов · 8 проектов
```

Обрати внимание: у Codex лимиты приходят от сервера и они точные, а у Claude
считаются локально и это оценка. Разница должна читаться с одного взгляда, но
не превращаться в дисклеймер на пол-экрана.

**3. Главное окно, вкладка «Сегодня».** Лента задач за день. У каждой:
название, проект, ветка, время начала, длительность, модель, число запросов,
токены. Сортировка по расходу. Реальные строки:

```
Тестирование локальных ИИ моделей с Ollama    Projects        276 запросов   87.3M
Проверить остановки в документации            ollama-bar      272 запроса    63.5M
—  (без названия)                             ollama-bar      238 запросов   62.1M
Обновить README с примерами скриншотов        ollama-bar      200 запросов   30.3M
Отредактировать задачи для GARM проектов      pilot           126 запросов   20.8M
Изучить репозиторий Meta Llama                ollama-bench    113 запросов   13.6M
Запустить задачу GARM-808 в работу            pilot            86 запросов   10.4M
Изменить статус задачи GARM-810               pilot            58 запросов    4.8M
```

Часть задач без названия — покажи, как выглядит эта строка, чтобы дыра не портила
ленту. Названия длинные и кириллические, числа большие — вёрстка должна это держать.

**4. Карточка задачи.** Раскрытая одна задача: таймлайн запросов, разбивка
токенов по типам (свежий ввод, запись в кэш, чтение кэша, вывод), список
инструментов с их стоимостью, затронутые файлы. Из этого экрана человек понимает,
почему конкретная задача обошлась дорого.

**5. Вкладка «Развёртка»** — самая интересная и самая сложная.
Надо показать одновременно две принципиально разные вещи:

- **Разовый расход**: инструмент сходил и принёс результат в контекст.
  `Bash` — 93 вызова, 24.0k токенов. `Read` — 20 вызовов, 19.3k. `Edit` — 45 вызовов, 3.6k.
- **Постоянный расход**: то, что лежит в начале промпта и переплачивается на
  каждом запросе. MCP-сервер, которым сегодня ни разу не пользовались, всё равно
  съел лимит своими описаниями инструментов. Каждая новая сессия стоит 28k токенов
  ещё до первого слова пользователя.

Второе — неочевидный и самый ценный вывод продукта, ради него всё затевалось.
Найди для этой пары форму. Не обязательно два графика рядом; возможно, одна
конструкция, где видно и то, и другое. Категории расхода: инструменты,
MCP-серверы, скиллы, плагины, сабагенты, картинки и скриншоты, хуки, стартовый
оверхед, пересборка кэша.

**6. Настройки.** Пути к логам, потолки лимитов по плану подписки, пороги
уведомлений, автозапуск, тема, скрыть тексты промптов.

**7. Состояния.** Пустое (агенты ещё не запускались), первичное индексирование
570 МБ логов, ошибка чтения, ни одного активного агента.

### Тон и визуальный язык

Прибор, а не витрина. Ближе к хорошему системному монитору, чем к аналитике для
маркетинга. Числа — моноширинным, они постоянно меняются и не должны прыгать.
Цвет несёт смысл (агент, статус, уровень тревоги), а не украшает. Плотно, но с
воздухом там, где взгляд цепляется.

Чего не надо: круговых диаграмм, градиентных карточек, огромных KPI-плашек с
одной цифрой на четверть экрана, иконок ради иконок, «ИИ-эстетики» с фиолетовыми
свечениями.

Две сущности требуют устойчивого визуального различия по всему приложению:
**Claude против Codex** и **точные данные против оценок**.

### Что отдать

Макеты всех семи пунктов в тёмной теме, ключевые — ещё и в светлой.
Плюс основа системы: палитра, шкала типографики, сетка отступов, состояния
компонентов (строка агента, полоса лимита, строка задачи, элемент развёртки).
Русский интерфейс.

## Заметки для себя, в промпт не входят

- Числа выше — из реального суточного среза: `out` 1.5M, `cache_write` 4.3M,
  `cache_read` 339M, 22 сессии. В макеты для «Сегодня» идёт суммарный вес 344.9M.
- Стоимость инструментов (Bash 24.0k / Read 19.3k / Edit 3.6k) посчитана
  маржинальным методом из `docs/plan.md` на сессии `ollama-bar`.
- 28k стартового оверхеда — фактический `cache_creation` первого запроса сессии
  на этой машине.
- Если дизайн придёт слабый на пятом экране — это ожидаемо, он самый трудный.
  Запасной ход: заказать его отдельным прогоном, дав только ось «разовое против
  постоянного» без остальных экранов.
