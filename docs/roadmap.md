# Roadmap

От пустой папки до подписанных инсталляторов. Каждый этап заканчивается
проверяемым результатом — не «написан парсер», а «команда отработала зелёным».

Колонка «кто»: **сам** — решение неочевидно и ошибка не ловится тестом;
**Codex** — объём с ясным критерием готовности (через скилл `delegate-to-codex`).
Объём: **S** — один заход, **M** — половина дня, **L** — день и больше.

Этот файл — индекс и единственное место, где живут статусы. Развёрнутые брифы
по этапам лежат в [`roadmap/`](roadmap/) и пишутся на веху вперёд.
Реализация дизайна разобрана отдельно:
[`roadmap/design-implementation.md`](roadmap/design-implementation.md).

## Архитектура

```
packages/core/            чистый TypeScript, ничего не знает про Electron
  sources/claude/         разбор ~/.claude/projects/*.jsonl + sessions/*.json
  sources/codex/          разбор ~/.codex/sessions/**/rollout-*.jsonl
  sources/types.ts        нормализованная модель — общая для обоих провайдеров
  index/                  SQLite, инкрементальный дочит по (файл, оффсет, inode)
  attribution/            маржинальная дельта, рекуррентная стоимость, категории
  limits/                 окна, точные у Codex, оценочные у Claude
  query/                  агрегаты под экраны: today, tasks, breakdown, live
apps/cli/                 agentmeter today|tasks|breakdown|limits|doctor|verify
apps/desktop/             Electron: main (трей, вотчер, IPC) + renderer (React)
design/                   макет из Claude Design — эталон для вёрстки
```

Ядро отдельным пакетом не ради красоты: CLI поверх него сверяет цифры в
терминале, не запуская GUI. Пока цифры не сошлись, рисовать нечего.

### Нормализованная модель (0.2)

```ts
type Provider = 'claude' | 'codex'

interface Session {
  id: string; provider: Provider
  cwd: string; project: string; branch?: string
  model?: string; entrypoint?: string      // cli | vscode | jetbrains | exec
  title?: string; firstPrompt?: string
  startedAt: number; endedAt: number
  parentSessionId?: string                 // сайдчейн сабагента
}

interface Request {                        // один вызов API
  sessionId: string; seq: number; requestId: string
  ts: number; model: string
  input: number; output: number
  cacheWrite: number; cacheRead: number
  reasoning?: number                       // Codex отдаёт явно
  contextTokens: number                    // занято окна на этом запросе
  skill?: string                           // attributionSkill
  isSidechain: boolean
  compacted: boolean                       // скачок префикса — компакт контекста
  synthetic: boolean                       // служебный вызов, не пользовательский ход
  tools: ToolCall[]
}

interface ToolCall {
  id: string; name: string
  kind: 'builtin' | 'mcp' | 'skill' | 'agent' | 'web'
  server?: string                          // для mcp__server__tool
  resultBytes: number                      // размер в логе — врёт, но нужен для дележа
  marginalTokens: number                   // посчитано атрибуцией — это правда
  hasImage: boolean
}
```

**1.3 блокирует всё.** Пока `verify` не зелёный, остальные этапы M1 строятся на
неизвестно чём.

Расследование продвинулось: недостающий класс найден — часть запросов к API в
транскрипт не пишется, но восстанавливается по разрыву цепочки кэша. Недобор
упал с 5–15% до ±3%, пять сессий из пятнадцати сходятся до токена. Осталась
хвостовая часть, следа не оставляющая. Заодно выяснилось, что сабагенты пишут
собственные транскрипты, а эталон Claude Code их недосчитывает. Подробности —
[`roadmap/1.3-verify.md`](roadmap/1.3-verify.md).

## Открытые вопросы — решить до кода, а не по ходу

| вопрос | почему нельзя отложить |
|---|---|
| Откуда недобор 5–15% против `lastModelUsage` | вся статистика врёт, пока не найдено |
| Вес `cache_read` в лимите подписки | разница между «считать» и «нет» — два порядка |
| Что считать границей дня | 5-часовое окно ходит через полночь; «сегодня» в локальной зоне, а `timestamp` в UTC |
| Одна сессия = одна задача? | resume и `--continue` плодят файлы; сайдчейны лежат отдельно |
| Ретеншн индекса | 570 МБ логов сегодня и растут ежедневно |
| `better-sqlite3` под Electron | нативный модуль, пересборка под каждую платформу; альтернатива — `node:sqlite` |
| Служебные вызовы Haiku | это расход пользователя или системный шум? влияет на все итоги |

## Как делегируется

Через скилл `delegate-to-codex`. Задача уходит, только если в бриф влезли четыре
вещи. Пример для 1.1, остальные пишутся по тому же шаблону:

> **Файлы:** создать `packages/core/src/sources/claude/*`. Не трогать ничего
> за пределами этой папки, `types.ts` в том числе.
> **Контракт:** типы из `packages/core/src/sources/types.ts` заданы, менять их нельзя.
> **Критерий:** `npm test -w packages/core -- claude` зелёный, все 8 фикстур
> из `fixtures/claude/` разбираются без исключений.
> **Данные:** `fixtures/claude/`, ожидаемый разбор в `fixtures/claude/*.expected.json`.

Без четвёртого пункта Codex сочиняет данные и уверенно рапортует об успехе,
поэтому фикстуры (0.6) делаю сам и до всех парсеров.

**Не делегируется:** контракты M0, модель атрибуции, калибровка лимитов,
`verify`, платформенная возня с треем, рекомендации по экономии. В первых
четырёх ошибка тихая — тест зелёный, а цифра врёт. В остальных критерий —
«выглядит правильно на трёх ОС».
