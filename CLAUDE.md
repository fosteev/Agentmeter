# Agentmeter

Локальный кросс-платформенный счётчик токенов для кодинг-агентов (Claude Code,
Codex). Трей, лимиты, задачи дня, развёртка расхода по инструментам,
MCP-серверам, скиллам и сабагентам. Всё считается из логов на диске; сетевых
вызовов у приложения три — проверка обновлений (5.4) и два запроса лимитов у
провайдеров (6.3, 6.4), — и каждый выключается настройкой, причём лимиты
выключены по умолчанию.

**Стек:** Electron + TypeScript + React, ядро парсинга отдельным пакетом.
**Состояние:** M3 закрыт весь, из M1 остался долг 1.9 (калибровка веса
`cache_read` — механика готова, копит наблюдения). Окно показывает день
целиком: лента с карточкой задачи, разрезы по часам, проектам и тикетам, «куда ушло сегодня» постоянным
против разового, настройки пятью разделами, русский и английский. **M4 закрыт
весь:** развёртка с советами по экономии, пересборка кэша и переплата за паузу,
картинки отдельной статьёй, история с хитмапом, уведомления, выгрузка в
CSV/JSON и состав статей префикса по наведению. **В M5 сделаны 5.1, 5.3, 5.4
и 5.5**: инсталляторы на три платформы, автозапуск, автообновление, README (английский, со снимками из макета) и
лицензия. Открыт 5.2 — подписи ждут сертификатов, которых у проекта нет. **В M6 сделаны
6.1–6.4**: живые сессии видно прямо в ленте (закреплены сверху, с текущим
запросом и расходом за ход), значок в menu bar на macOS ведёт нативный процесс,
а настоящий процент лимита можно спросить у провайдера напрямую — у Anthropic
вторым источником к хуку строки состояния, у OpenAI вторым источником к
роллаутам; оба выключены по умолчанию. **В M7 сделаны 7.1 и 7.2:** пять окон
лимита разведены табами провайдеров — попап открывается на самом тревожном, а у
таба за кликом горит точка его уровня, — и снимок пересобирается кнопкой в шапке
и по `⌘R`. Там же нашлось 7.4: потолки лимитов Claude больше не выбираются
планом — они измеряются калибровкой 1.9 вместе с весом `cache_read`, и
заявленный тариф им больше не мешает. А в 7.5 из раздела «Лимиты» убрано то,
что не работало: карточки потолков (мерить их не из чего) и хук строки
состояния (в VS Code её нет вовсе) — на их месте выбор, какие окна показывать в
попапе, а сам хук снимается с чужого файла настроек при старте.

## Что важно знать до первой строки кода

1. **Расход считается не размером результата в логе, а ростом промпта.**
   `ctx(N+1) − ctx(N) − output(N)` = сколько тул реально добавил в промпт, где
   `ctx` — весь промпт запроса (`contextTokens`). Формула одна на обоих
   провайдеров. Проверено: на одном `Read` в лог легло 382 КБ, а в промпт ушло
   2873 токена; у картинок в логе ≈200 байт на токен против 2.7 у текста.
   Сверено с независимым источником — Codex пишет в результате команды
   `Original token count`, медиана отношения к нашей дельте 1.00 на 519
   вызовах. Подробности и правила — [`1.6-attribution.md`](docs/roadmap/1.6-attribution.md).

2. **Часть запросов к API в транскрипт не пишется.** Отсюда недобор 5–15% по
   чтению кэша при наивной агрегации. Восстанавливаются по разрыву цепочки
   кэша: `cr(N+1) > cr(N) + cw(N)` означает незаписанный запрос между ними,
   и разрыв даёт его стоимость целиком. Плюс сабагенты (usage только
   последнего запроса, в `toolUseResult` вызова `Agent`) и служебный Haiku
   (в транскрипте нет вовсе). После реконструкции 5 из 16 сессий сходятся
   до токена, остальные в пределах ≤ 3.3% — это хвостовые прогревы после
   последнего ответа, следа не оставляющие. Принято как **измеренная
   поправка**: такие сессии показываются со знаком `≈`. Подробности —
   [`1.3-verify.md`](docs/roadmap/1.3-verify.md), прогнать —
   `node --experimental-strip-types scripts/probe/verify-live.ts`.

3. **`requestId` не уникален построчно.** Один ответ API пишется несколькими
   строками `assistant`. Сумма по строкам завышает в разы, а первая строка
   недобирает: `output_tokens` в ней частичный, стриминг дописывает его по
   ходу ответа. Схлопывать по `requestId`, беря максимум по каждому полю.

4. **Сабагенты пишут свои транскрипты** в
   `projects/<slug>/<sessionId>/subagents/agent-<agentId>.jsonl` плюс
   `.meta.json` с `agentType` и `toolUseId`. Эталон Claude Code их не читает —
   берёт только usage последнего запроса из `toolUseResult`, вшестеро меньше.
   То есть по сабагентам наш подсчёт точнее эталона. У воркфлоу они лежат на
   уровень глубже (`subagents/workflows/wf_<id>/`), и таких файлов больше, чем
   обычных; рядом `journal.jsonl` — не транскрипт, отбирать по префиксу `agent-`.
   **Внутри такого файла лежит `sessionId` родителя, а не свой:** 591 файл на
   диске давал всего 330 уникальных идентификаторов, у одной сессии 17
   сабагентов с общим id. Идентичность сабагента — из имени файла
   (`agent-<id>.jsonl`), иначе в индексе они перезапишут друг друга и родителя,
   и расход просто станет меньше, без единого исключения.

5. **Codex пишет `token_count` дважды на один запрос** — в 174 сессиях из 311.
   Тот же класс ошибки, что `requestId` у Claude: суммирование по записям
   завышает почти вдвое, и выглядит это здорово. Повтор виден по неподвижному
   `total_token_usage`. Зато у Codex сверка встроена в формат: сумма запросов
   обязана сойтись с накопительным итогом до токена — так и есть на всех 311
   сессиях. Где источник даёт такой итог, сверка с ним — обязательный тест.
   Второй подвох там же: `token_count` пишется **между** `function_call` и
   `function_call_output`, поэтому наивный сбор вызовов задваивал каждый —
   именованным с нулём байт на своём запросе и безымянным с байтами на
   следующем. Суммы токенов при этом сходились, и проба молчала (1.6).

6. **Стартовый префикс лежит в логе блоками, но не весь.** Листинги скиллов и
   сабагентов, имена отложенных тулов, инструкции MCP и вложенные `CLAUDE.md`
   пишутся записями `attachment` дословно — их можно посчитать в байтах, а
   **имена лежат там же готовыми массивами**: `names` у `skill_listing`,
   `addedTypes` у `agent_listing_delta`, `addedNames` у `deferred_tools_delta`,
   `path` у `nested_memory` (271 сессия из 271, 288 из 288, 123 из 123). Считать
   их разбором текста листинга нельзя: форм в нём две вперемешку — `- имя` и
   `- имя: описание`, — и регулярка по второй давала 12 скиллов вместо 36 (4.9).
   Системного промпта и схем тулов там нет, они остаются остатком. И главное:
   когда в наборе есть `ToolSearch`, схемы MCP в префикс не едут вовсе — сервер
   serena стоит 349 токенов вместо 6007, в 17 раз меньше. Совет «отключи
   неиспользуемый сервер» без различения режимов врёт на порядок. Подробности —
   [`1.7-prefix.md`](docs/roadmap/1.7-prefix.md).

7. **Вес `cache_read` в лимите подписки известен только у Codex.** Там он
   измерен подбором на окнах одной модели: ≈ 0.2, причём ноль проигрывает
   втрое (CV 5% против 17%) — то есть чтение кэша считается, но со скидкой.
   У Claude разница между «считать» и «не считать» по-прежнему два порядка
   (339M против 4.3M за сутки), и лимиты помечены оценкой, пока не набран
   журнал 1.9. Подбором его там не берут: процент окна у Claude **есть** —
   см. пункт 21, — поэтому вместо перебора решается линейная система.
   Переносить 0.2 по аналогии нельзя: провайдер другой.

8. **Вид окна лимита — по его длине, не по имени слота.** До Codex CLI 0.145.0
   `primary` был пятичасовым, с 0.145.0 стал недельным, а `secondary` исчез.
   Разбор по слотам показывает недельный расход как пятичасовой, молча. Там же
   ещё две ловушки: процент окна — **максимум** наблюдений, а не последнее
   (снимок лимита приезжает из ответа API и при параллельных запросах отстаёт,
   худший случай 57% → 1% и обратно за 13 секунд), и окно фиксированное,
   якорится на первом запросе после истечения прошлого. Подробности —
   [`1.8-limits.md`](docs/roadmap/1.8-limits.md).

   **И четвёртая, найденная в 6.4: окно живёт, пока провайдер о нём говорит.**
   Запись `token_count` перечисляет весь набор действующих лимитов, а не тот,
   что изменился, поэтому длина, не названная более поздней записью, там и
   заканчивается. Без этого правила окно доживает до собственного `resets_at`,
   показывая всё это время свой последний процент: 13 июля аккаунт на сутки
   оказался на бесплатном плане, Codex сообщил месячное окно и довёл его до
   100%, — и `Codex · месячное окно 100%` висело в попапе месяц спустя. Записи,
   не назвавшие **ни одного** окна (`plan_type: null`, оба слота пусты), не
   закрывают ничего: это «данных пока нет». Замер: 15 407 наблюдений, пропадание
   длины ровно одно и совпадает со сменой плана.

9. **Реестр живых процессов есть только у Claude, и написан он не по
   контракту.** `~/.claude/sessions/<pid>.json` кладёт в `entrypoint`
   `claude-vscode` и `claude-desktop` — без нормализации 8 живых сессий из 9
   схлопываются в `unknown`. Там же `procStart` записан **в UTC**, хотя
   выглядит локальным временем (`Mon Aug 10 07:11:48 2026` у процесса,
   стартовавшего в 10:11:48 по местному), а `ps` печатает локальное: наивная
   сверка отвергает каждый живой pid. Сам файл пишется один раз при старте, его
   `mtime` активности не показывает — только транскрипт. У Codex реестра нет
   вовсе (проверено по всему `~/.codex`), поэтому живость там — свежесть
   роллаута, и в снимке это помечено `liveness: 'silence'` против `'process'`.

10. **Состояние агента — из того, чем кончился транскрипт, а не из тишины.**
    Агент, закончивший ход, и агент, думающий над длинным ответом, молчат
    одинаково. Разница в последней **значимой** записи, и брать «тип последней
    записи» нельзя: после значимой в лог ложатся учётные (`attachment`,
    `file-history-snapshot`, `last-prompt`, `mode`, `queue-operation`), и
    последней в файле оказывается именно учётная у 233 файлов из 251. Плюс
    порядок записей не хронологический (`stop_hook_summary` с меткой 08:00:11
    после записи с меткой 08:08:04), сайдчейн пишет свой `end_turn` и без
    отсева объявляет родителя ждущим, а `stop_sequence` у модели не встречается
    вовсе — все 17 таких записей сочинил сам CLI (`model: "<synthetic>"`).
    У Codex ход размечен провайдером: `task_started` / `task_complete` /
    `turn_aborted`, и переносить туда правила Claude — терять точность даром.
    Правила и замеры — [`live/state.ts`](packages/core/src/live/state.ts).

11. **`ELECTRON_RUN_AS_NODE=1` превращает Electron в обычную ноду, и молча.**
    Переменная выставлена в терминалах внутри VS Code и наследуется всем, что
    оттуда запускается. Под ней бинарник Electron стартует нодой:
    `require('electron')` отдаёт строку с путём вместо модуля, `app` равен
    `undefined`. Опасно не падение, а обратное — смоук, случайно запущенный под
    ней, соберёт снимок через `node:sqlite` (он есть и в простой ноде) и выйдет
    нулём, «доказав» работу Electron, которой не было. Поэтому проверка
    подлинности (`process.versions.electron`) стоит первой строкой main, запуск
    идёт только через `apps/desktop/scripts/launch.js`, а смоук обязан **падать**
    под этой переменной — это отдельная проверка пробы, а не примечание.

    **`open` из такого терминала заражает и обычный запуск приложения.**
    Замерено 12 августа: `open /Applications/Agentmeter.app` из оболочки с этой
    переменной поднимает приложение нодой, и оно завершается за 90 мс с кодом 0
    — ни окна, ни значка, ни строчки в логе (в `--stderr` видно только
    `bad option` от ноды). Выглядит это как «сборка сломана», а сломана
    оболочка: `env -u ELECTRON_RUN_AS_NODE open …` поднимает то же приложение
    нормально.

12. **Размер контекстного окна известен только у Codex.** `model_context_window`
    приезжает в каждом `token_count` и уже лежит в индексе. У Claude его нет ни
    в транскрипте, ни в имени модели: строка `claude-opus-5` встречается с
    контекстом до 495 548 токенов, то есть покрывает и окно 200k, и окно 1M —
    выбирают их отдельными пунктами интерфейса, а в лог это не попадает.
    Таблица «модель → окно» промахнулась бы впятеро на 44 сессиях из 243.
    Поэтому у Claude знаменатель выводится из наблюдений (наименьшее
    стандартное окно, вмещающее максимум за 30 дней) и помечается оценкой —
    [`live/context.ts`](packages/core/src/live/context.ts).

13. **Доля, которую видно числом, считается в main; доля, которая живёт только
    как длина полоски, — в окне.** Правило задано в 3.0 и дальше не
    переизобретается. «25% дневного расхода» и «41% постоянного» приезжают
    посчитанными: у них есть текст рядом и второй потребитель, и разойтись им
    есть с чем. Высота столбика часа относительно самого высокого часа — это
    подгонка под доступную ширину, у неё второго потребителя нет. Ровно поэтому
    у `HourBucket` лежит готовый `total`: без него окно складывало бы
    провайдерские куски ради поиска максимума, а это уже второй счёт расхода.
    Границы правила расписаны в шапке блока «Главное окно (M3)» в
    [`packages/ipc/src/index.ts`](packages/ipc/src/index.ts).

14. **Путь файла берётся из объявленного параметра инструмента, и «затронутый»
    значит «изменённый».** У Claude путь лежит в `file_path` у `Read`, `Edit` и
    `Write` (3133 из 3133 у `Edit`), у Codex — в заголовках `*** Update File:`
    патча (1927 вызовов из 1927 одним форматом). А вот чтение у Codex идёт
    обычным шеллом, и структуры под него в логе нет вовсе: считай карточка
    прочитанные файлы, один и тот же список значил бы у Claude «прочитано и
    изменено», а у Codex «изменено». Разбирать командную строку `Bash` нельзя по
    той же причине, по которой нельзя угадывать что угодно ещё: похожее на путь
    есть у 6284 вызовов из 8778. Пути живут в `tool_files`
    ([`sources/files.ts`](packages/core/src/sources/files.ts),
    [`query/files.ts`](packages/core/src/query/files.ts)), MCP-правки в них не
    попадают — дыра измерена, 48 вызовов против 3997.

15. **Пустых экрана три, а не один.** «Индекс ещё не собран», «за день не
    работали» и «фильтр отсёк всё» — разные слова, и различить их можно только
    флагами `emptyIndex`/`emptyDay`. Второй считается **до** сужения
    (`hasRequests` в ядре): посчитай его после фильтра — и человек, выбравший
    Codex в клодовый день, увидит «за сегодня ничего», хотя день полон.
    Симметрично: сужение обязано доезжать до итога, часов и проектов, а не
    только до ленты, иначе шапка покажет весь день над лентой одного проекта, и
    каждое число по себе останется настоящим.

16. **День раскладывается через `Σ (ctx + output)`, постоянное — это
    `Σ min(P, ctx)`, разовое — остаток.** `contextTokens` собран из
    `input + cacheWrite + cacheRead` у обоих провайдеров, то есть привычная
    сумма четырёх видов токенов — она же, записанная иначе (28 824 запроса,
    расхождений ноль). Ограничение сверху не для красоты: компакт роняет
    контекст ниже префикса, и без него разовое уходит в минус — таких запросов
    1 из 28 824, и на нём держится всё свойство. Разовое считается вычитанием, а
    не суммой вызовов, и внутри него лежит **перечитывание** результатов на
    каждом следующем запросе: 98.2% постоянного — это тоже перечитывание, а не
    первая запись. Отсюда главный вывод продукта: цена включённого сервера — его
    размер, умноженный на число запросов. Модель —
    [`4.1-split.md`](docs/roadmap/4.1-split.md).

17. **Компакт — обвал контекста, пересборка кэша — обвал только кэша, и в usage
    след у них один.** Чтение кэша проваливается до 8–23% прежнего префикса и
    там, и там; различает их `contextTokens`. Правило «упало чтение кэша, значит
    компакт» держалось в парсере до 4.4 и ошибалось на живых логах **в 90
    случаях из 91** — карточка задачи писала «сжатие контекста» над столбиком,
    который никуда не провалился. Где провайдер размечает компакт сам
    (`compact_boundary` у Claude, `context_compacted` у Codex), его слово
    сильнее вывода. Пересборка при этом **не добавляет дню ни одного токена**:
    тот же промпт едет либо чтением, либо записью, и `Σ (ctx + output)` от паузы
    не меняется — блок 4.4 показывает состав расхода, а не лишний расход.
    Подробности — [`4.4-cache.md`](docs/roadmap/4.4-cache.md).

18. **Кэш промпта живёт час, и срок лежит в логе.** У Claude 42.88M из 44.44M
    записанных токенов уходят в `ephemeral_1h`, пятиминутный срок бывает почти
    только у сабагентов. Зашитые «пять минут» из макета дали бы четыре пустые
    корзины и вывод «переплаты нет» там, где её 9.5M, поэтому всё, что меряется
    паузой, считается **кратностями срока из `cache_write_1h`/`cache_write_5m`**.
    У Codex записи в кэш нет в логе вовсе (`cache_write = 0` на всех 11 994
    запросах), а его кэш осыпается постепенно — счётного события «кэш пересобран»
    там нет, и блока для Codex не существует.

19. **Claude Code удаляет свои транскрипты сам, и индекс их переживает.**
    `cleanupPeriodDays` (по умолчанию 30 суток) стирает старые логи; на живой
    машине самый старый уцелевший лог Claude моложе 23 дней против 191 дня
    роллаутов Codex. С этого момента разобранное в индексе — единственная
    запись о расходе, поэтому пропавший файл **не забывается**: строка
    `sources` получает `vanished_at`, данные остаются. Раньше первого
    уцелевшего лога Claude измеренного нуля не бывает — там `≈` при расходе и
    `null` при его отсутствии: замер по `~/.claude/history.jsonl` даёт 92 дня
    внутри покрытия, когда Claude работал, а индекс не знает ни одного запроса,
    и 31 из них показывался нулём. Срока хранения в конфиге нет и не будет —
    подробности в «Ретеншн индекса» ([`docs/roadmap.md`](docs/roadmap.md)).

20. **Служебные вызовы Haiku — расход пользователя, но посчитать его нечем.**
    Заголовки сессий и сводки «пока вас не было» идут отдельной моделью и в
    транскрипт не пишутся вовсе. В эталоне это 4.85M из 373.0M (1.30%), но
    доля неоднородна: цена стоит по разу на сессию, поэтому на крупном проекте
    это 0.1%, а на мелком — до 29.9%. Оценивать их числом = придумать
    коэффициент; принято как измеренная поправка, как хвостовые прогревы в 1.3.

21. **Настоящий процент лимита Claude отдаёт только `statusLine`.** В
    транскрипте его нет ни в каком виде, но команде строки состояния Claude
    Code подаёт на stdin JSON, и в нём с 2.1.x лежат `rate_limits.five_hour` и
    `.seven_day` (дробный `used_percentage` и `resets_at` **в секундах**), а
    рядом `context_window.context_window_size`. Ключ `rate_limits` появляется
    только после первого запроса к API в сессии, а в `-p` строка состояния не
    зовётся вовсе. Ни сети, ни чужих токенов это не требует — тем и выбрано:
    `cachedUsageUtilization` из `~/.claude.json` протухает на полсуток, а
    oauth-эндпоинт недокументирован и 429-ит. Отсюда `w` и `cap` решаются
    линейной системой `p/100 · cap = I + W + O + w · R`, где вес обязан
    совпасть между окнами разной длины, а окна с чужим расходом обрезаются —
    процент считается по аккаунту, а не по машине. Подробности —
    [`1.9-usage.md`](docs/roadmap/1.9-usage.md).

    **Хук из продукта снят в 7.5, и это не отмена находки, а её граница:**
    строку состояния рисует только терминальный CLI. В VS Code её нет вовсе, и
    на живой машине установленный хук за месяц дал **ноль** наблюдений против
    54 ответов провайдера. Журнал с тех пор наполняет только запрос к Anthropic
    (пункт 23), разбор stdin остался в ядре вместе с эталоном, а хук снимается
    с чужого файла настроек разовой уборкой при старте.

22. **`Tray` из Electron на macOS 26 в menu bar не встаёт.** Пункт создаётся, но
    система паркует его за нижней кромкой экрана: `getBounds()` отдаёт `y`,
    равный высоте экрана, Accessibility показывает у процесса ту же координату,
    и там же оказываются пункты **всех** Electron-приложений на машине (Cursor,
    Docker Desktop) — тогда как нативные соседи стоят на панели. Дело не в
    картинке: пункт вообще без картинки, одним текстом, уезжает туда же, а
    нативный `NSStatusItem` в тех же условиях встаёт нормально. Поэтому на macOS
    значок ведёт отдельный процесс на Swift
    ([`menubar/AgentmeterBar.swift`](apps/desktop/menubar/AgentmeterBar.swift),
    мост — [`main/menubar.ts`](apps/desktop/src/main/menubar.ts)), на Windows и
    Linux остаётся `Tray`. Рисование туда **не переехало**: растр считает
    `tray-icon.ts`, хелпер получает готовый PNG. Опасна здесь тишина —
    приложение работает, индекс дописывается, а выглядит незапущенным.

23. **`/api/oauth/usage` пускает Chromium и не пускает Node.** Второй источник
    настоящих лимитов (6.3) обязан ходить `net.fetch` из Electron: перед
    эндпоинтом стоит Cloudflare, и отсекает он не по заголовкам, а по отпечатку
    TLS. Замер одним токеном и одними заголовками: `curl` — 200, Chromium — 200,
    `fetch` из Node — 403, `node:https` — 403, `node:http2` — 403; обе очевидные
    гипотезы (заголовки, версия протокола) проверены порознь и отвергнуты. Врать
    про `User-Agent` при этом не нужно — 200 приходит и на `Agentmeter`. Опасен
    не отказ, а его вид: с Node-фетчем источник не заработал бы ни у кого, а
    выглядело бы это как «Anthropic не принял токен», и человек пошёл бы
    перелогиниваться в Claude Code. Второй подвох там же — **проценты целые**
    (`19`, не `19.0000001`), тогда как `statusLine` отдаёт дробные; одна точка с
    квантованием при малом проценте разводит потолки окон на 7.66% при пороге
    5%, то есть блокирует калибровку целиком. Отсюда `CALIBRATION.minIntegerPct`
    и поле `source` в журнале. **Границы окна оттуда же:** наш якорь промахнулся
    на три часа (16:40–21:40 UTC против 19:40–00:40) при том, что пятичасовой
    паузы в запросах не было вовсе, — лимит считается по аккаунту, и окно могло
    начаться с запроса, которого у нас нет. Поэтому где провайдер ответил, окно
    Claude берётся у него целиком, а не дополняется процентом: процент от одного
    интервала рядом с «сброс через» от другого — две правды, дающие ложь —
    [`6.3-oauth-usage.md`](docs/roadmap/6.3-oauth-usage.md).

24. **У Codex второй источник лимитов чинит не число, а его возраст.** Процент
    в роллаутах есть и он точный — но написан в момент запроса. Замер 12
    августа: лог от 10-го сообщал 44% недельного окна со сбросом 14-го,
    `chatgpt.com/backend-api/wham/usage` в тот же момент — 0% со сбросом 19-го;
    обе половины строки на экране были неверны. Эндпоинт взят у ClaudeBar, и
    оттуда же три вещи, которые пришлось отвергнуть: разбор окон **по имени
    слота** (на текущем CLI недельное окно лежит в `primary`, пункт 8), чтение
    заголовков `x-codex-*` (их в ответе нет вовсе) и **рефреш токена с записью
    обратно в `~/.codex/auth.json`** — у OpenAI refresh-токены одноразовые, и
    наш обмен разлогинил бы человека из самого Codex. Токен только читается,
    срок берётся из его же полезной нагрузки, а нечитаемый срок просроченным не
    считается. Ходить обязан `net.fetch`: из Node этот эндпоинт отвечает 403,
    как и соседний у Anthropic. Подробности —
    [`6.4-codex-oauth.md`](docs/roadmap/6.4-codex-oauth.md).

## Тексты интерфейса

Ни одной строки интерфейса в коде: всё через `t()` из
[`packages/core/src/i18n/`](packages/core/src/i18n/) — каталог общий на main,
окно и CLI. Три правила, которые нарушаются по невнимательности:

- **`t()` нельзя звать на верхнем уровне модуля.** Константа посчитается один
  раз при загрузке и застынет на языке запуска. В константах лежат ключи.
- **Термины — из глоссария**, а не из головы: `cache read`, `subagent`,
  `context window` уже написаны провайдером в логах.
- **Новый ключ в узком месте — с потолком длины** (`i18n/limits.ts`). Перевод,
  вылезший за край, выдавливает число молча и только на одном языке из двух.

Проверки: полнота каталогов и форм — типом (`i18n/check.ts`), длина и выбор
языка — `packages/core/test/i18n.test.ts`, отсутствие литералов —
`apps/desktop/test/i18n-sweep.test.ts`.

## Границы честности

Продукт измерительный, поэтому врать цифрами нельзя даже из вежливости.
Всё, что оценка, помечается оценкой (в макете — штриховкой и знаком `≈`).
Если часть расхода принципиально не восстановима из логов — это документируется
как измеренная поправка, а не заминается.

## Делегирование

**Оставшиеся этапы делаются здесь, без Codex** — во всех открытых строках
роадмапа в колонке «кто» стоит «сам». Так что скилл `delegate-to-codex` без
отдельной просьбы не зовём.

От делегирования остались две вещи, которые работают и на себя. Первая — бриф по
шаблону [`docs/roadmap/_template.md`](docs/roadmap/_template.md): файлы,
контракт, команда-критерий, данные для сверки; без четвёртого пункта данные
сочиняются, кем бы ты ни был. Вторая — проверку, которую не видели красной,
считать несуществующей: в 2.2, 2.5, 2.6, 2.7, 2.8, 3.0 и 3.2 собственные
проверки переживали мутацию, и каждый раз ошибка была по существу.
